# dream4x 計算モデル(実装版)

サーバーの実装(`packages/server/src` の match.ts / bot.ts / visibility.ts / rewards.ts / lobby.ts / map.ts / modifiers.ts と `packages/shared/src`)を正として、試合中・試合後の計算処理をモデル化したもの。各項目は **目的 → 入力 → 式または擬似コード → 使う定数 → 計算例** の順で書く。定数の値は 2026-10-05 時点の shared から転記した(定数名を併記するので、値が変わったときは shared を正とする)。機能の説明は `docs/機能仕様書.md`、構成は `DESIGN.md` を参照。

記法: `dt` は 1 tick の内部時間(秒)、`now` は試合開始からの内部時間(ms)。`mods.*` は 2章で合成した有効係数。`round` は四捨五入、`floor` は切り捨て。

---

## 1. tick の処理順序と時間

**目的**: 1 tick で何をどの順に更新するかを固定し、順序依存(例: 到着→交戦→回復)を明確にする。

**入力**: `dtMs`(= `MATCH.tickMs × TIME_SCALE`)。

**処理**(`Match.step(dtMs)`):

```
now += dtMs; dt = dtMs / 1000
1. checkAbort            人間全員が切断していれば無効化判定(18.4)
2. updatePhaseAndSpawns  フェーズ切替、拠点の予告/出現
2b. updateNpc            NPC文明の生産と 1 秒ごとの行動(13章)
3. updateAiControl       放置判定、botThinkMs ごとのボット思考(16章)
4. updateTraining        生産完了した部隊を首都に出現(集結点があればそこへ。23章)
5. updateResearch        研究の完了、予約列の開始、定期的な全域可視(20章)
6. updateIncome          拠点収入と維持費(3章・21章)
7. updateUpgrades        拠点強化の完了(22章)
8. updateCrossings       渡河点の建設進捗・解体完了(9章)
9. updateStances         態勢による自動行動: retreat の退避/復帰、aggressive の追跡(23章)
10. updateMovement       部隊の経路追従、NPC文明の直進(5章)
10b. updateStrikes       砲撃支援の着弾(31章)
11. updateCombat         交戦と撃破・制圧・奪取、砲座(6〜7章・22章)。HP0の部隊を除去
12. updateRegen          部隊の回復、拠点・渡河点の回復(7, 10章)
13. updateTickets        チケット減少と脱落判定(11〜12章)
14. updateReveals        文明の判明(14章)
15. updateRanks          暫定順位
16. checkEnd             終了判定(12章)
```

**時間**:
- 内部時間 `now` は tick ごとに `tickMs × TIME_SCALE` 進む。実時間 100ms ごとに 1 tick(`setInterval(MATCH.tickMs)`)。スナップショットは `snapshotMs / tickMs = 2` tick に1回。
- 試合内の全ての時刻(保護期間、出現時刻、クールダウン、再建可能時刻)は内部時間。
- 放置判定だけは実時間: `Date.now() − lastInputAt > MATCH.idleTakeoverMs` で `aiControlled = true`。AI代行中の指示(ボット経由)は操作とみなさない(`aiActing` フラグ)。人間の操作が来ると解除。
- ボットの思考は内部時間で `MATCH.botThinkMs` ごと。

**定数**: `MATCH.tickMs = 100`、`MATCH.snapshotMs = 200`、`MATCH.idleTakeoverMs = 120000`、`MATCH.botThinkMs = 2000`、`DEFAULT_TIME_SCALE = 1`(環境変数 `TIME_SCALE` で上書き)。

**計算例**: `TIME_SCALE=4` のとき 1 tick で内部時間は 400ms 進み、30分の試合は実時間 7.5分で終わる。放置判定は実時間なので、放置から 120 秒(内部時間 8 分相当)で AI 代行になる。

## 2. 係数の合成(modifiers.ts)

**目的**: 文明・研究・アドオンの倍率を1つの `EffectiveMods` にまとめ、部隊生成時と各 tick で参照する。

**入力**: 文明 `civ`、研究済みノード `researched[]`、アドオン `addons[]`。

**式**: 16種類の係数それぞれについて、初期値 1 に **乗算** で積み上げる。

```
mods[k] = 1
  × CIVS[civ].mods[k]                               (あれば)
  × Π RESEARCH_TREES[civ][n].effect[k]  (n ∈ researched、あれば)
  × Π ADDONS[a].passive[k]              (a ∈ addons、あれば)
k ∈ { attack, hp, speed, vision, supplyIncome, researchIncome, trainTime, baseHp, bleedTaken,
      upkeep, buildSpeed, crossingHp, scoutVision, scoutSpeed, turret, stealth }
```

倍率以外の効果(`researchUnlocks`、研究完了のたびに再計算):

```
squadLimit       = SQUAD_LIMIT + Σ effect.squadLimit   (研究済みノードの合計)
siegeUnlocked    = いずれかの研究済みノードが effect.unlockSiege
baseUpgradeMax   = max(1, 研究済みノードの effect.baseUpgradeMax)   … 拠点強化の上限レベル(22章)
revealIntervalMs = 研究済みノードの effect.revealIntervalMs の最小(0 なら無し。20章)
unlockAA / unlockAir / unlockNaval は段階1では効果なし(研究はできる)
```

適用先:

| 係数 | 適用先 |
| --- | --- |
| attack | 部隊の `dmg` 行列全体(対陸上/航空/水上/構造物。25章) |
| hp | 部隊生成時の最大HP(4章) |
| speed | 1 tick の移動量(5章) |
| vision | 部隊の視界半径(14章)。拠点・渡河点の視界には掛けない |
| supplyIncome / researchIncome | 拠点収入(3章) |
| trainTime | 生産時間(4章) |
| baseHp | 所有拠点の最大HP(開始時・再建時・制圧時・研究時に再計算。22章の強化倍率と乗算) |
| bleedTaken | チケット減少(11章)。チーム内プレイヤーの平均 |
| upkeep | 維持費(21章) |
| buildSpeed | 渡河点の建設進捗(9章)と拠点強化の時間(22章) |
| crossingHp | 自分が完成・奪取した渡河点の最大HP(9章) |
| scoutVision / scoutSpeed | 斥候だけに追加で掛かる視界・速度(5章・14章) |
| turret | 強化拠点の砲座の攻撃(22章) |
| stealth | 非戦闘・非移動の自部隊が敵に見つかる距離の倍率(14章) |

研究で係数が変わると `refreshMods` が、所有拠点の最大HP(`baseMaxHp`、22章)、自部隊の最大HP(`round(SQUADS[type].hp × hp)`)、自分が所有する渡河点の最大HP(`round(spec.hp × crossingHp)`)を更新し、現在HPは比率を保つ。アドオンの `startSupply` / `startResearch` / `extraStartSquad` は開始時に一度だけ適用(補給 `START_SUPPLY + startSupply`、初期部隊 `CIVS[civ].startSquads + extraStartSquad`)。

**定数**: `SQUAD_LIMIT = 3`、`START_SUPPLY = 200`、`START_RESEARCH = 0`。文明 mods は `CIVS`、研究 effect は `RESEARCH_TREES`、アドオン passive は `ADDONS`。

**計算例**: 文明 corp(`supplyIncome 1.3, trainTime 0.85, attack 0.95`)で研究 b1「量産ライン」(corp 版: `supplyIncome 1.25, trainTime 0.9`)と b2x「維持費削減」(`upkeep 0.7`)を取り、アドオン p_armor(`hp 1.1`)を装備:

```
supplyIncome = 1.3 × 1.25 = 1.625
trainTime    = 0.85 × 0.9 = 0.765
attack       = 0.95
hp           = 1.1
upkeep       = 0.7
(他は 1)
```

## 3. 収入

**目的**: 拠点ごとの補給・研究収入を所有プレイヤーに積む。

**入力**: 各拠点の `active, owner, ownerPlayer, tier, contested`、プレイヤーの `fallen, supplyHalfUntilMs, mods`。

**式**(毎 tick、拠点ごと):

```
対象: active かつ owner ≥ 0 かつ ownerPlayer が存在し、そのプレイヤーが fallen でない
half   = (now < supplyHalfUntilMs) ? 0.5 : 1            … 根回しの代償(18.3)
sector = (contested === false かつ tier ≠ hq) ? SECTOR_BASE_RESEARCH_FACTOR : 1
lv     = BASE_UPGRADES[tier][level − 1].income           … 強化レベルの収入倍率(22章)
supply   += BASES[tier].supplyPerSec   × lv × mods.supplyIncome   × half   × dt
research += BASES[tier].researchPerSec × lv × sector × mods.researchIncome × dt
```

収入のあとに同じ tick で維持費を引く(21章)。

- `ownerPlayer` は首都=建てた人、制圧拠点=制圧した人(7章)。チームの他メンバーには入らない。
- 陥落中のプレイヤーは収入を受け取らない(首都は `active=false` なので首都分も止まる)。
- クライアントへは `floor(supply)`, `floor(research)` を送る。内部は小数で保持。

**定数**: `BASES.*.supplyPerSec` = hq 4 / small 2 / mid 3 / grand 5、`researchPerSec` = hq 0 / small 0.4 / mid 1.0 / grand 2.0、`SECTOR_BASE_RESEARCH_FACTOR = 0.3`、`MATCH.sabotageMs = 30000`、`BASE_UPGRADES.*[].income` = Lv1 1 / Lv2 1.3(hq 1.25)/ Lv3 1.6(hq 1.5)。

**計算例**: pmc(`supplyIncome 1.1`)が首都(Lv1)+ 自陣小拠点2つ(contested=false、Lv1)+ 島の小拠点1つ(contested=true、Lv2)を保持:

```
補給/秒 = (4 + 2 + 2 + 2×1.3) × 1.1 = 11.44   → 1 tick(0.1秒)で +1.144(維持費は別途)
研究/秒 = (0.4×0.3 + 0.4×0.3 + 0.4×1.3×1) × 1.0 = 0.76
```

## 4. 生産

**目的**: 補給を払って部隊を予約し、時間後に首都へ出現させる。

**入力**: `train{type}`。プレイヤーの `supply, squadLimit, siegeUnlocked, fallen, training[]`、現在の部隊。

**擬似コード**(`Match.train`):

```
if fallen → error
if type == siege and !siegeUnlocked → error
used = {自分の部隊の slot} ∪ {training の slot}
if |used| ≥ squadLimit → error
if supply < SQUADS[type].cost → error
supply −= cost
slot = 1 から数えて used に無い最小の番号
training.push({ type, slot, readyAtMs: now + SQUADS[type].trainMs × mods.trainTime })
```

出現(`updateTraining` → `spawnSquad`):

```
hp = maxHp = round(SQUADS[type].hp × mods.hp)
pos = 首都の中心 + 半径 40 のランダム方向(マップ内にクランプ)
stance = "aggressive"
集結点 rally が設定されていれば plan(s, rally)(生産完了した部隊のみ。23章)
```

開始時の初期部隊も同じ `spawnSquad`(slot は空き最小番号。集結点の対象外)。

**定数**: `SQUADS.assault = {cost 120, trainMs 12000, hp 300}`、`scout = {60, 6000, 120}`、`siege = {180, 18000, 260, research a2}`、`aa = {140, 14000, 240, research a3}`、`gunship = {220, 20000, 220, research a4}`、`boat = {200, 18000, 320, research d4}`、`SQUAD_LIMIT = 3`。研究要件を満たさない種類は error、水上は `dock` が無ければ error(27章)。

**計算例**: 2章の corp(`trainTime 0.765`, `hp 1.1`)が強襲を生産: 補給 −120、`readyAtMs = now + 12000 × 0.765 = now + 9180ms`、出現時 HP = `round(300 × 1.1) = 330`、出現後は維持費 2.4×0.7 = 1.68/秒(21章)。部隊 01 と 03 を持っていれば slot は 2。

## 5. 移動

**目的**: 地形(川・山)と渡河点を考慮した経路で部隊を動かす。

**入力**: `move{squadId, pos}`、地形グリッド `terrain`、渡河点の状態、部隊の `type, team`。

**通行可能セルの決め方**(`passableFor(team, type)`、渡河点が変わるまでキャッシュ):

```
passable(idx) = terrain.cells[idx] == land
             or idx ∈ ∪{ c.cells | c.built and c.owner == team and !(c.kind == ropeway and type == siege) }
```

**経路計算**(`plan` → shared の `findPath`):
- 出発セルと目的セルを `cellIndexOf`(80px 格子)で求め、8近傍 A*。斜め移動は両隣の直交セルが通行可能なときだけ(角抜け禁止)。コストは直交 1、斜め √2、ヒューリスティックは octile 距離。
- 到達可能なら `path` = 経由セルの中心列(同一方向は間引き、最後は目的地そのもの)、`unreachable=false`。
- 到達不能なら「目的セルにヒューリスティックで最も近い到達済みセル」までの経路を返し `unreachable=true`。経路が空なら `path=undefined`。
- `target` は常に指示した目的地を保持する。

**経路追従**(毎 tick、`followPath`):

```
step = SQUADS[type].speed × mods.speed × (type == scout ? mods.scoutSpeed : 1) × dt
remain = step
while remain > 0 and path 非空:
  wp = path[0]; d = |pos − wp|
  if d ≤ remain: pos = wp; path.shift(); remain −= d       … 経由点到達、次へ
  else: pos += (wp − pos)/d × remain; remain = 0
if path が空: path = undefined; unreachable でなければ target = undefined(到着)
```

到達不能の部隊は最寄り地点で `target` を持ったまま待機し、渡河点の状態変化(建設完了・奪取・解体)のたびに `onCrossingsChanged` が **目的地を持つ全部隊** の経路を現在位置から再計算する。通れるようになればそのまま進む。NPC文明の部隊は地形を無視して目標へ直進(13章)。

**定数**: `SQUADS.*.speed` = assault 110 / scout 190 / siege 75、`MAP.fogCell = 80`(地形セル = 霧セル、40×40)。

**計算例**: society(`speed 1.15`)の斥候: `step = 190 × 1.15 × 0.1 = 21.85` / tick(c2x「偵察ドローン」`scoutSpeed 1.1` があれば 24.0)。次の経由点まで 15 なら、その tick で経由点に乗り、残り 6.85 を次の経由点へ進む。島の拠点を指示して橋がなければ環状の川の手前の陸セルで止まり `unreachable=true`。自チームが橋Iを完成させた tick に経路が引き直され、次の tick から渡り始める。

## 6. 交戦

**目的**: 射程内の敵へ毎 tick 自動で攻撃する。移動は止めない。

**入力**: 全部隊(プレイヤー・NPC文明)、拠点、渡河点、防御施設、`mods.attack`、攻撃可否行列 `SQUADS[type].dmg`(25章)。

**攻撃側の選択**(部隊ごと、`updateCombat`。詳細は 26章):

```
range = raider ? RAIDER.range : SQUADS[type].range
dmg(kind) = unitDmg(s, kind)                       … 25章(部隊は SQUADS[type].dmg[kind] × mods.attack)

1) 敵部隊: 自分以外で HP>0、(raider なら team ≥ 0 の部隊、部隊なら他チームか raider)、dmg(相手の種類) > 0、|pos − o.pos| ≤ range
   → 最も近い1体(対空車両は射程内に航空がいれば航空)に dmg × dt。engaged=true。以降の候補は見ない
2) 守備NPC(部隊のみ、dmg(ground) > 0): 中立(owner<0)で active、guardHp>0、|pos − b.pos| − radius ≤ range → guardHp −= dmg(ground) × dt
3) 防御施設(部隊のみ、dmg(structure) > 0): 他チームの砲座・対空陣地(地雷原は見えないので対象外)、|pos − d.pos| − 20 ≤ range → hp −= dmg(structure) × dt
4) 拠点・渡河点(dmg(structure) > 0): active、(raider なら owner ≥ 0、部隊なら owner ≠ 自チーム)、守備NPCが残っていない、|pos − b.pos| − radius ≤ range
   首都は now < protectedUntilMs なら候補外
   渡河点(部隊のみ): built かつ owner ≠ 自チーム、min(|pos − ends[0]|, |pos − ends[1]|) − radius ≤ range
   → 拠点と渡河点のうち距離(半径を引いた値)が最も近いもの: hp −= dmg(structure) × dt
```

**守備NPCの反撃**(拠点ごと): 中立で `guardHp>0` の拠点は、`|s.pos − b.pos| ≤ radius + SQUADS[s.type].range` を満たす最も近い部隊1体(NPC文明の部隊も対象)に `guardAttack × (航空なら NPC_AIR_FACTOR) × dt`。守備NPCは動かない。

**砲座**(強化拠点、22章): 所有拠点で `level ≥ 2` のものは、守備NPCの反撃の後に、中心から `BASE_UPGRADE_RANGE` 以内の最も近い敵部隊(NPC文明含む)に `turretAttack × mods.turret × (補給線が切れていれば SUPPLY_LINE.turretFactor) × (航空なら NPC_AIR_FACTOR) × dt`。

**防御施設**(28章): 砲座・対空陣地は射程内で撃てる最も近い敵部隊に `DEFENSES[kind].dmg[種類] × dt`、地雷原は敵の陸上部隊が踏むと一撃。

**NPC文明の部隊**: 対象は「他チームの部隊(攻撃可否行列どおり)」「中立拠点の守備NPC」「NPC所有でない拠点」。渡河点・防御施設は攻撃しない。

**engaged**: tick の最初に全部隊 false。攻撃した部隊と攻撃を受けた部隊は true(10章の回復停止に使う)。`contestedBy` は攻撃を受けた拠点/渡河点に攻撃側チームを入れ、tick ごとにリセット。

**HP0 の処理**: 部隊は `damageSquad` で撃破(7章・11章・17章)。拠点は `damageBase` → 攻撃側が制圧できる部隊(陸上。NPC文明の陸上部隊も)なら 首都は陥落(8章)、NPC本拠なら陥落(13章)、それ以外は制圧(7章)。航空・水上が 0 にした拠点は 0 のまま所有が変わらず、制圧できる部隊の次の一撃で処理される。渡河点は奪取(9章。航空・水上なら予定地に戻る)。防御施設は破壊(28章)。HP0 の部隊は tick の最後にまとめて除去されるので、同じ tick 内では攻撃を受け続けない(`hp ≤ 0` で早期 return)。

**定数**: `SQUADS.*.range` = assault 120 / scout 100 / siege 150 / aa 200 / gunship 140 / boat 180。dmg 行列は 25章。`BASES.*.guardAttack` = small 10 / mid 40 / grand 90(hq は guardHp 0 なので守備なし)。`NPC_AIR_FACTOR = 0.5`。`RAIDER.range = 110`。`MATCH.hqProtectionMs = 300000`。

**計算例**: pmc(`attack 1.12`)の装甲強襲 1 部隊が中立の小拠点(半径 60)の中心から 150 の位置にいる: `150 − 60 = 90 ≤ 120` で射程内。守備NPCに毎 tick `dmg.ground 30 × 1.12 × 0.1 = 3.36`。同じ位置に敵の偵察が 100 の距離にいれば、優先順位 1 により偵察に 3.36 を与え、守備NPCは殴らない。守備NPCの反撃は `10 × 0.1 = 1.0` / tick(相手が攻撃ヘリなら 0.5)。

## 7. 制圧と回復

**目的**: 守備NPC → 拠点HP の順で削り、HP0 で所有を移す。所有拠点は時間で回復する。

**制圧**(`capture`、首都以外):

```
by がプレイヤー部隊:
  owner = by.team; ownerPlayer = by.owner; guardHp = 0
  maxHp = round(BASES[tier].hp × mods(by.owner).baseHp)
  hp    = round(maxHp × 0.3)
  score(by.owner).captures += 1; イベント capture(制圧チーム)
by が NPC文明の部隊(13章。NPC所有に):
  owner = −1; ownerPlayer = undefined; guardHp = BASES[tier].guardHp; maxHp = hp = BASES[tier].hp
旧所有者がいればイベント lost(旧チーム)
```

守備NPCが残っている中立拠点は、6章の優先順位により `guardHp` が 0 になるまで拠点HPを削れない。

**回復**(`updateRegen`、毎 tick):

```
対象: active かつ owner ≥ 0 かつ hp < maxHp かつ now − lastHitMs ≥ 1000
hp = min(maxHp, hp + BASES[tier].regenPerSec × dt)
```

`lastHitMs` は守備NPCまたは拠点HPが削られた tick に更新される。首都も同じ規則で回復する。

**定数**: `BASES.*.hp` = small 400 / mid 900 / grand 1800、`guardHp` = 200 / 900 / 2500、`regenPerSec` = hq 5 / small 3 / mid 4 / grand 6。

**計算例**: pmc 強襲 2 部隊(対守備 67.2/s、対拠点 44.8/s)で小拠点を攻める: 守備 `200 / 67.2 ≈ 3.0秒`、拠点HP `400 / 44.8 ≈ 8.9秒`、合計約 11.9 秒。制圧後は `maxHp = round(400 × 1.0) = 400`、`hp = 120`。agency(`baseHp 1.3`)が制圧した場合は `maxHp 520, hp 156`。放置すると `3/s` で約 93 秒で全快。

## 8. 首都の陥落と再建

**目的**: 首都HP0 の損失と、チケットを払っての再建。

**陥落**(`hqFall`、保護期間外に hp ≤ 0):

```
hq.active = false
p.fallen = true; p.rebuildAvailableAtMs = now + MATCH.rebuildDelayMs
p.supply = 0; p.research = 0; p.training = []        … 研究済みノードは保持
mine = p の部隊を 段階 rank → 経験値 xp の昇順に並べたもの; lose = floor(|mine| / 2)
  先頭 lose 体(練度の低い方)を hp=0 にして squad_lost を送る(チケットは減らない)
loss = min(team.tickets, MATCH.ticketLossOnHqFall)
team.tickets = max(0, team.tickets − MATCH.ticketLossOnHqFall)
攻撃側がプレイヤーチームなら:
  そのチームの全プレイヤーの supply += MATCH.hqFallRewardSupply
  落とした部隊のオーナー: hqFalls += 1, ticketsDealt += loss
イベント hq_fall(全員) → 脱落判定(12章)
```

**再建**(`rebuild`):

```
条件: fallen、チーム未脱落、now ≥ rebuildAvailableAtMs、team.tickets ≥ MATCH.rebuildCost(かつ > 0)
位置: 生きている味方の首都があれば その中心 + 半径 220 のランダム方向(100..3100 にクランプ)、無ければ元の位置
      → nearestLand で最寄りの陸セル中心へ寄せる
team.tickets −= rebuildCost
hq.active = true; maxHp = round(BASES.hq.hp × mods.baseHp); hp = round(maxHp × 0.5)
hq.protectedUntilMs = now + MATCH.rebuildProtectionMs
fallen = false; イベント rebuild(全員)
```

**定数**: `MATCH.ticketLossOnHqFall = 150`、`hqFallRewardSupply = 300`、`rebuildDelayMs = 60000`、`rebuildCost = 150`、`rebuildProtectionMs = 60000`、`BASES.hq.hp = 1500`。

**計算例**: 部隊 3 体のチームの首都が 12:00 に陥落: `floor(3/2) = 1` 体を失い、チケット 640 → 490、攻撃側の各プレイヤーに補給 +300。13:00 以降に再建でき、agency(`baseHp 1.3`)なら `maxHp 1950, hp 975`、14:00 まで保護。

## 9. 渡河点

**目的**: 橋・索道の建設・通行・奪取・解体をモデル化する。

**建設開始**(`build{crossingId}`):

```
条件(順に判定、違反は error):
  未建設 / 自分が fallen でない / spec.research があれば研究済み
  他チームが建設中でない(先着優先) / 自チームが建設中でない
  自分の部隊が ends のどちらかから spec.radius + CROSSING_ADJACENT 以内
  supply ≥ spec.cost
supply −= cost; builder = team; builderPlayer = 自分; progress = 0
イベント crossing_build_start(自チーム)
```

**進捗**(`updateCrossings`、毎 tick):

```
builder チームの部隊が1体でも隣接していれば progress += dt × 1000 / spec.buildMs × mods(builderPlayer).buildSpeed
  (離れている間は止まり、進捗は保持。他チームは引き継げない)
progress ≥ 1 で完成: built = true; owner = builder; ownerPlayer = builderPlayer
  maxHp = hp = round(spec.hp × mods(builderPlayer).crossingHp); progress/builder は消す; イベント crossing_built(所有チーム)
```

**通行**: 所有チームのみ(5章)。索道は攻城部隊が通れない。

**攻撃・奪取**(`damageCrossing`): 6章の優先順位で他チームの部隊が `siege × dt` を与える。`hp ≤ 0` で:

```
owner = 攻撃側チーム; ownerPlayer = 攻撃した部隊のオーナー
maxHp = round(spec.hp × mods(ownerPlayer).crossingHp); hp = round(maxHp × 0.3)
解体中ならキャンセル(demolishAtMs を消す)
イベント crossing_captured(奪った側と奪われた側の両チーム) → 全部隊の経路を再計算
```

**解体**(`demolish{crossingId}`): 建設済みで自チーム所有、解体中でないこと。`demolishAtMs = now + spec.demolishMs`。到達した tick に未建設(owner −1, hp 0, progress なし)へ戻り、イベント crossing_demolished(旧所有チーム)→ 経路再計算。

**回復**: built かつ `now − lastHitMs ≥ 1000` で `hp += spec.regenPerSec × dt`。

**視界**: 所有する建設済み渡河点の `pos` を中心に半径 `spec.vision`(14章)。渡河点は拠点重みに数えない(11章)。

**定数**(`CROSSINGS`、`crossingKey(kind, cls)` で引く):

| key | cost | buildMs | hp | demolishMs | radius | vision | regen | 研究 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| bridge1 | 200 | 90000 | 500 | 8000 | 50 | 220 | 3 | なし |
| bridge2 | 160 | 60000 | 700 | 8000 | 55 | 220 | 3 | c1 |
| bridge3 | 240 | 90000 | 900 | 10000 | 60 | 220 | 3 | c2 |
| ropeway1 | 140 | 60000 | 600 | 8000 | 50 | 260 | 3 | c3 |
| ropeway2 | 220 | 80000 | 800 | 10000 | 55 | 260 | 3 | c4 |

`CROSSING_ADJACENT = 60`(match.ts)。

**計算例**: 橋I: 端点から `50 + 60 = 110` 以内に部隊を置いて build → 補給 −200。隣接し続けると 1 tick で `0.1 × 1000 / 90000 ≈ 0.00111` 進み、90 秒で完成(HP 500)。d4x「工兵隊」(`buildSpeed 2, crossingHp 1.3`)なら 45 秒で完成し HP 650。30 秒で離れると 1/3 のまま止まり、戻れば残り 60 秒。敵の pmc 攻城(`60 × 1.12 = 67.2/s`)に端点から射程内で殴られると `500 / 67.2 ≈ 7.4 秒` で奪取され、HP 150 で相手のものになる。

## 10. 部隊の回復

**目的**: 低HPの部隊が首都へ退避する意味を持たせる。

**式**(`updateRegen`、毎 tick、プレイヤー部隊ごと):

```
条件: !engaged かつ team ≥ 0 かつ hp < maxHp かつ 自分の首都が active
      かつ |pos − hq.pos| ≤ BASES.hq.radius + 60
hp = min(maxHp, hp + maxHp × MATCH.squadHealPerSecNearHq × dt)
```

味方の首都では回復しない(自分の首都のみ)。再集結(c_rally)は発動時に即 `hp = min(maxHp, hp + maxHp × 0.4)`。

**定数**: `MATCH.squadHealPerSecNearHq = 0.04`、`BASES.hq.radius = 90`(判定半径 150)。

**計算例**: 強襲(maxHp 300)が HP 150 で首都に戻ると毎秒 12 回復し、ボットの復帰閾値 90%(270)まで 10 秒。

## 11. チケット

**目的**: 拠点の保持差による継続的な減少(bleed)と、損失による即時減少。

**入力**: 各チームの保持拠点、フェーズ、`mods.bleedTaken`、根回しの状態。

**重み**:

```
weight(T) = Σ_{b: active, owner = T} (b.tier == grand ? MATCH.grandBaseWeight : BASES[b.tier].weight)
```

**bleed**(毎 tick、未脱落かつ tickets > 0 のチーム T ごと):

```
O       = T 以外の未脱落チームの集合(空なら減少なし)
avg     = (Σ_{o∈O} weight(o)) / |O|
deficit = min(MATCH.grandBaseWeight, max(0, avg − weight(T)))
taken   = T のプレイヤーの mods.bleedTaken の平均
phase   = (phase == late) ? MATCH.lateBleedMultiplier : 1
sab     = (now < T.sabotageUntilMs) ? 2 : 1
tickets(T) = max(0, tickets(T) − deficit × MATCH.bleedPerBasePerSec × phase × taken × sab × dt)
```

**即時減少**:

```
部隊撃破(NPC文明・守備NPCによる撃破も同じ): MATCH.ticketLossPerSquad × SQUADS[type].ticketLossFactor × (1 + VETERANCY.ticketPerRank × rank) / config.perTeam(チーム合計のチケットは人数で変えないため人数で割る)
首都陥落: MATCH.ticketLossOnHqFall(8章)。陥落時に失う部隊の半数ぶんは減らない
再建: MATCH.rebuildCost
```

**定数**: `MATCH.startTickets = 1000`(チーム合計。人数で変えない)、`bleedPerBasePerSec = 0.2`、`lateBleedMultiplier = 2.0`、`grandBaseWeight = 3`、`ticketLossPerSquad = 8`、`ticketLossOnHqFall = 150`。`BASES.*.weight` = hq 0 / small 1 / mid 2 / grand 3。`ticketLossFactor` = assault 1.0 / scout 0.5 / siege 1.2。bleedTaken: agency 0.9、研究 c3「封鎖対策」0.75。

**計算例**: 中盤、A=小3+中1(重み 5)、B=小3(3)、C=小1(1)。

```
A: avg = (3+1)/2 = 2 → deficit 0 → 減らない
B: avg = (5+1)/2 = 3 → deficit 0 → 減らない
C: avg = (5+3)/2 = 4 → deficit = min(3, 3) = 3 → 3 × 0.2 = 0.6/秒(36/分)
   終盤なら ×2 = 1.2/秒。C が agency なら 0.6 × 0.9 = 0.54/秒。根回しを受けていればさらに ×2
C が強襲を1体失うと即 −8、斥候なら −4、攻城なら −9.6(3人チームの構成ならそれぞれ ÷3 = −2.67 / −1.33 / −3.2)
```

重みの差が 3 を超えても減少は頭打ちになる(大拠点1つ分が上限)。

## 12. 脱落・順位・終了判定

**脱落**(`checkElimination`、首都陥落と bleed のたび):

```
eliminated = 全プレイヤーが fallen かつ (tickets ≤ 0 または tickets < MATCH.rebuildCost)
eliminatedAtMs = now; イベント team_eliminated(全員)
```

全員が陥落していてもチケットが再建費以上なら、再建待ちとして試合に残る。チケット 0 でも首都が立っていれば脱落しない。脱落チームは bleed の対象からも「他チーム平均」の計算からも外れる。

**順位**(`ranking`、毎 tick と終了時):

```
alive = 未脱落チームを tickets 降順 → weight 降順 → チーム番号昇順
dead  = 脱落チームを eliminatedAtMs 降順(後に脱落した方が上) → チーム番号昇順
ranking = alive ++ dead;  rank(T) = 位置 + 1
```

**終了**(`checkEnd`、毎 tick の最後):

```
未脱落チームが 1 以下 → endedBy = "elimination"
now ≥ MATCH.durationMs   → endedBy = "timeout"
```

**定数**: `MATCH.rebuildCost = 150`、`MATCH.durationMs = 1800000`。

**計算例**: 終了時に A 520 / B 520 / C 0(未脱落、首都あり)。A の重み 4、B の重み 2 なら 1位 A、2位 B、3位 C。C が 25 分に脱落、D(4チーム制のとき)が 20 分に脱落していれば C が D より上。

## 13. NPC文明(現地勢力)

**目的**: 中央の島に本拠を持つ第三勢力が、中盤以降すべてのチームに等しく圧力をかける。徘徊NPC(RAIDER の出現)は廃止し、この NPC に統合。

**入力**: `NPC_CIV`、`BASES.stronghold`、本拠 `stronghold`(owner `NPC_TEAM`)、NPC所有の拠点、NPC部隊(`team = NPC_TEAM`, `npc = "raider"`, `npcMul`)。

**配置**(15章の生成の最後):

```
strongholdAngle = teamAngle(0) + sector/2     … 隣り合う陣営の中間 = 各陣営の橋Iから最も遠い角度
pos = nearestLand(polar(center, NPC_CIV.strongholdRadius, strongholdAngle), 島内)
本拠: tier stronghold, owner NPC_TEAM, hp 2500, guardHp 0, protectedUntilMs = NPC_CIV.firstSpawnAtMs
初期保有: 本拠に近い順に島の小拠点 initialBases 個を owner NPC_TEAM, guardHp 0 に
```

**生産**(`updateNpc`、本拠が active のとき):

```
now ≥ firstSpawnAtMs かつ now ≥ nextNpcSpawnAtMs のとき:
  t = clamp(now / durationMs, 0, 1)
  nextNpcSpawnAtMs = now + spawnIntervalStartMs + (spawnIntervalEndMs − spawnIntervalStartMs) × t
  NPC部隊数 < maxSquads なら spawnNpc()
spawnNpc(type?):
  roster = (phase == late) ? lateRoster : roster;  type = roster[index++ % length]
  grow = npcStrength() = 1 + growthPerMin × (now / 60000)
  hp = maxHp = round(SQUADS[type].hp × grow); npcMul = grow; pos = 本拠の中心 + 半径 40
  イベント npc_spawn(全員)
unitDmg(NPC部隊, kind) = SQUADS[type].dmg[kind] × npcMul     … 攻撃可否行列どおり(航空の NPC は航空のまま)
```

**行動**(1 秒ごと `NPC_THINK_MS`、優先順に割り当て):

```
1) 救援: 直近 NPC_RESCUE_WINDOW_MS 以内に被弾した NPC拠点ごとに、未割当で最も近い部隊を向かわせる
2) 守り: 残りを本拠に近い順に並べ、max(1, ceil(部隊数 / 2)) 体を本拠の半径内に留める(外にいれば本拠へ)
3) 残り: 最寄りの非NPC拠点(active、owner ≠ NPC_TEAM、中立含む、保護中の首都を除く)へ
npcGoTo(u, b): |u − b| > radius + range − 10 なら target = b の中心、そうでなければ停止
移動: 地形を無視して target へ直進(5章の advance)。速度は SQUADS[type].speed(係数なし)
交戦: 6章の規則(敵部隊 → 中立拠点の守備NPC → 拠点。渡河点・防御施設は撃たない)
```

**制圧と報酬**:

```
NPC が拠点を 0 に(陸上のみ): owner = NPC_TEAM, ownerPlayer なし, guardHp 0, maxHp = 基準, hp = 30%, level 1
  イベント npc_captured(全員)。収入は無い(3章の owner < 0)。回復は通常どおり(7章)
プレイヤーが NPC拠点を 0 に: 通常の制圧(7章、captures+1)に加えて
  supply += NPC_CIV.captureRewardSupply; research += captureRewardResearch; イベント npc_base_lost(全員)
NPC部隊の撃破: 撃破した部隊のオーナーに RAIDER.killRewardSupply / killRewardResearch、npcKills+1(17章)
NPC が首都を 0 に: 8章の陥落(byTeam = NPC_TEAM、攻撃側の報酬は無し)
```

**本拠の陥落**(`strongholdFall`、陸上のプレイヤー部隊が hp ≤ 0 に):

```
本拠: active = false, hp = 0
NPC部隊: 全て hp = 0(撃破報酬なし)
NPC拠点: owner = −1, guardHp = 基準の守備, hp = maxHp = 基準, level 1
落としたチームの各プレイヤー: supply += strongholdRewardSupply, research += strongholdRewardResearch
落とした部隊のオーナー: captures += 1
イベント npc_stronghold_fallen(全員)。以後 NPC は生産しない(npcPublic().alive = false)
```

**チケットと順位**: NPC は `teams[]` に無いので、11章の「他の未脱落チーム」の平均に入らず、NPC拠点の重みはどのチームにも数えない。NPC に落とされた部隊のチケット損失は通常どおり。

**可視**: NPC は視界を持たない(`teamVision` は呼ばれない)。NPC部隊・拠点はプレイヤーの通常の可視判定で見える。`Snapshot.npc` = `{ alive, strength: round(npcStrength × 100)/100, baseCount: NPC所有の active 拠点(本拠を除く), squadCount, strongholdId }`。

**定数**: `NPC_TEAM = −2`、`NPC_CIV = { strongholdRadius 380, initialBases 1, spawnIntervalStartMs 90000, spawnIntervalEndMs 40000, firstSpawnAtMs 240000, growthPerMin 0.08, roster [assault, assault, aa, assault, siege], lateRoster [assault, gunship, aa, siege, assault], maxSquads 8, captureRewardSupply 150, captureRewardResearch 30, strongholdRewardSupply 400, strongholdRewardResearch 100 }`、`BASES.stronghold = { hp 2500, radius 100, vision 400, regenPerSec 4, weight 0 }`、`NPC_THINK_MS = 1000`、`NPC_RESCUE_WINDOW_MS = 3000`(match.ts)。

**計算例**: 4 分に最初の NPC(装甲強襲)が出現: `grow = 1 + 0.08 × 4 = 1.32`、HP `round(300 × 1.32) = 396`、対地 `30 × 1.32 = 39.6/秒`。次の出現は `90000 + (40000 − 90000) × (4/30) ≈ 83.3 秒後`。20 分の個体は `grow 2.6`、装甲強襲なら HP 780。本拠を 20 分に落とすと、落としたチームの各プレイヤーに補給 400・研究 100。

## 14. 可視判定(霧)

**目的**: チーム単位の視界を求め、プレイヤーごとのスナップショットを可視範囲に絞る。

**視界円の集合**(`teamVision(team)`):

```
circles = { (b.pos, BASES[b.tier].vision) | b.active, b.owner == team }
        ∪ { (c.pos, CROSSINGS[key].vision) | c.built, c.owner == team }
        ∪ { (s.pos, squadVision(s)) | s.team == team }
        ∪ { (d.pos, DEFENSES.watchtower.vision) | d は完成した自チームの観測塔で、敵の妨害圏内にない }   … 補給線に依存しない
squadVision(s) = SQUADS[s.type].vision × mods(s.owner).vision × (s.type == scout ? mods.scoutVision : 1)
各円の半径 r は × jamFactorAt(center, team)(敵の妨害塔の圏内なら jamFactor を重ねて乗算。観測塔は圏内なら円ごと無効。28章)
jamUntilMs(電波妨害、31章)中は全ての円の r × 0.5(乗算)。全域観測の円は妨害を受けない
all = チーム内の誰かが now < revealUntilMs(衛星照会、または研究の定期可視。20章)
sees(p, factor = 1) = all or ∃circle: |p − center| ≤ r × factor
```

**隠密**(`stealthFactor`、`jamShield`、`hideFactor`、`seesUnit`): 敵部隊 u を見つけられるかは `sees(u.pos, f)` で判定し、

```
stealth = 煙幕中なら 0、(u.engaged または u.target あり または NPC文明) ? 1 : mods(u.owner).stealth
shield  = u のチームの完成した妨害塔の圏内にいれば jamFactor(複数なら最小)、いなければ 1
f = min(stealth, shield)
```

つまり c4x「隠密行動」(`stealth 0.5`)を持つ側の、非戦闘かつ移動していない部隊は、相手の視界半径の半分まで近づかれないと見えない。自チームの部隊は常に見える。

**visibleCells**: 全セル(40×40)について中心 `((col + 0.5) × 80, (row + 0.5) × 80)` がいずれかの円内なら index を含める。`all` なら全セル。

**スナップショットに含めるもの**(`buildSnapshot`):

| 対象 | 条件 |
| --- | --- |
| 拠点 | `owner == 自チーム` または `sees(pos)` |
| 部隊 | `team == 自チーム` または `seesUnit`(隠密を考慮した `sees(pos, f)`) |
| 渡河点 | 自チームが所有(建設済み)または自チームが建設中、または `sees(pos)` / `sees(ends[0])` / `sees(ends[1])` |
| teams[].civs | 自チームのプレイヤー + `known` に入った敵プレイヤー |
| events | そのプレイヤーのキュー(全体告知・自チーム宛・自分宛)を送信時に空にする。上限 200 件 |

含めなかった拠点・渡河点はクライアントが最後に見た状態を保持する。

**文明の判明**(`updateReveals`、毎 tick、チーム T ごと):

```
敵プレイヤー p について: (p の首都が active かつ sees(hq.pos)) または (p の部隊のいずれかが seesUnit)
→ T.known に p を追加、イベント civ_revealed(T)。一度判明したら戻らない
```

**定数**: `BASES.*.vision` = hq 420 / small 240 / mid 300 / grand 360、`SQUADS.*.vision` = assault 260 / scout 420 / siege 220、`CROSSINGS.*.vision` = 橋 220 / 索道 260、`MATCH.revealMs = 10000`、`FOG_COLS = FOG_ROWS = 40`。

**計算例**: intel(`vision 1.3`)の斥候: 半径 `420 × 1.3 = 546`(c2x「潜入斥候」`scoutVision 1.6` があれば 874)。斥候が (1600, 1600) にいると、セル (20, 20) の中心 (1640, 1640) は距離 56.6 で可視、セル (27, 20) の中心 (2200, 1640) は距離 601 で不可視。敵の首都中心が 546 以内に入った tick で相手の文明が判明する。相手が society の c4x「影の行軍」(`stealth 0.4`)を持ち、その部隊が停止・非戦闘なら `546 × 0.4 = 218` まで近づかないと見えない。

## 15. マップ生成(map.ts)

**目的**: seed から決定的に、拠点・地形・渡河点を配置する。

**乱数と角度**:

```
N = config.teams(2〜4)、perTeam = config.perTeam(1〜3)
rng = mulberry32(seed); rot = rng() × 2π; sector = 2π / N
teamAngle(t) = rot + t × sector;  center = (1600, 1600)
polar(c, r, θ) = c + r × (cos θ, sin θ) をマップ内 [140, 3060] にクランプ
```

**地形**(セル中心 `(cx, cy)` ごとに、`r = |セル中心 − center|`、`ang = atan2`):

```
山塊(環の上、索道I): ∃t: massifInner ≤ r ≤ massifOuter かつ |ang − (teamAngle(t) + 30°)| ≤ 10°
環状の川(等級1):      上記でなく ringInner ≤ r ≤ ringOuter
放射状の境界川(各 t、方向 u = (cos b, sin b), b = teamAngle(t) + sector/2):
  along = (セル中心 − center)·u, perp = |(セル中心 − center) × u|
  along < radialStart       → 対象外
  along ≤ radialClass2End   → perp ≤ halfWidth[2] なら川(等級2)
  along ≤ radialClass3End   → perp ≤ halfWidth[3] なら川(等級3)
  それ以降                   → perp ≤ outerMassifHalf なら山(索道II)
判定順: 山塊 → 環 → 放射。山と川は重ならない
```

**拠点**(`nearestLand(grid, p, accept)`: p のセルが陸で accept を満たせばそのまま、そうでなければチェビシェフ距離 1, 2, … の順に走査し、陸かつ accept を満たす最初のセル中心):

```
首都(チーム内 index i、人数 n): spread = (n > 1) ? ((i / (n−1)) × 2 − 1) × 15° : 0
      polar(center, MAP.hqRadius, teamAngle(t) + spread)
      accept = 区画内(r > ringOuter + 60 かつ |ang − teamAngle(t)| < sector/2 − 5°)
自陣の小拠点 ×(n×2): hqCenter = polar(center, hqRadius, teamAngle(t)); k = 0..n×2−1, side = (k 偶数 ? +1 : −1), tierOffset = floor(k/2) × 12°
      polar(hqCenter, 350 + rng()×150 + floor(k/2) × 60, teamAngle(t) + 180° + side × (40° + tierOffset + rng()×12°)), accept = 区画内, contested=false
島の小拠点 ×1/陣営: polar(center, islandSmallR, teamAngle(t) + (rng()−0.5)×16°), accept = 島内(r < ringInner − 60), contested=true
中規模 ×1/陣営: polar(center, MAP.midBaseRadius, teamAngle(t) + sector/2), accept = 島内, active=false, spawnAtMs=midPhaseAtMs, contested=true
大拠点: center, active=false, spawnAtMs=latePhaseAtMs, contested=true
```

**渡河点**(`makeCrossing(grid, id, kind, cls, pos, dir)`):

```
ends: pos から ±dir に 16 ずつ最大 600 進み、最初に陸になるセルの中心(マップ外に出たら作らない)
cells: 両端の間を 8 ずつサンプルし、非陸セルを順に集める。
       直前のセルから斜めに移ったときは、直交の連結セル(prev の行 × 現在の列)が非陸なら追加(角抜け禁止対策)
maxHp = CROSSINGS[key].hp; owner = −1; built = false
配置: b1_t = polar(center, bridge1R, teamAngle(t)), dir = 放射方向
      r1_t = polar(center, ropeway1R, teamAngle(t) + 30°), dir = 放射方向
      b2_t / b3_t / r2_t = center + u × (bridge2Along / bridge3Along / ropeway2Along), dir = u に直交
```

陣営数 N によらず、環の川・山塊・島は同じ寸法。放射状の境界川と b2/b3/r2 は N 本、b1/r1/島の小拠点/中規模は各陣営1つ(渡河点は合計 5N、小拠点は N×perTeam×2 + N)。N=2 では境界は 2 本(角度 ±90°)。

**定数**(`TERRAIN_LAYOUT`、map.ts): `ringInner 660, ringOuter 780, massifAngleDeg 30, massifHalfDeg 10, massifInner 620, massifOuter 820, radialStart 660, radialClass2End 1050, radialClass3End 1400, halfWidth {2: 80, 3: 120}, outerMassifHalf 110, bridge1R 720, ropeway1R 720, bridge2Along 880, bridge3Along 1230, ropeway2Along 1480, islandSmallR 430`。shared: `MAP = { width 3200, height 3200, fogCell 80, hqRadius 1150, midBaseRadius 600 }`、`MIN_TEAMS = 2`、`MAX_TEAMS = 4`、`MAX_PLAYERS_PER_TEAM = 3`、既定 `TEAM_COUNT = 3`、`PLAYERS_PER_TEAM = 1`。

**計算例**: N=3、`rot = 0` のとき チーム0 の首都は (2750, 1600)。perTeam=3 なら spread = −15°, 0°, +15° で 3 つの首都が (2711, 1302), (2750, 1600), (2711, 1898) に並び、自陣の小拠点は 6 つ。境界 b = 60° の方向 u = (0.5, 0.866)。セル中心 (2040, 2360) は `along = 440×0.5 + 760×0.866 = 878`、`perp = |440×0.866 − 760×0.5| = 1.0` → 等級2の川。橋II は center + u × 880 = (2040, 2362) を中心に u と直交する方向に端点を探す。

## 16. ボットの判断(bot.ts)

**目的**: ボットと AI 代行を、人間と同じ操作 API で動かす。

**周期**: 内部時間 2 秒ごと(`BOT_THINK_MS`)。脱落チームは何もしない。

**順序と規則**(`think`):

```
(4) 陥落中: now ≥ rebuildAvailableAtMs かつ tickets ≥ rebuildCost なら rebuild。それ以外は何もしない
(1) 生産: 部隊数 + 生産中 < squadLimit のとき(開放済みで、水上は港があること)
      敵の航空を一度でも見ていて対空車両が無ければ aa、序盤で偵察を持たず部隊が0なら scout、
      自走砲 → 攻撃ヘリ → 哨戒艇 を各1(持っていなければ)、それ以外 assault
      supply ≥ cost なら train
(1b) 態勢: 新しい部隊に一度だけ stance を設定。装甲強襲 = retreat、攻撃ヘリ = aggressive、それ以外(偵察・自走砲・対空・哨戒艇)= hold
(2) 研究: 予約列が空のとき、フェーズごとの優先順位で最初に canResearch を満たすものを research(開始か予約)
      序盤: b1 → a1 → c1 → (中盤の列)
      中盤: 序盤の列 → a2系 → b2系 → d1 → b3 → a3 → (終盤の列)
      終盤: 序盤の列 → a3 → a4x → b3 → b4系 → c2系 → c3 → c4系 → d2 → d3系 → d4x → (中盤の列)
      「系」は排他ペアで、文明ごとの固定の好み EXCLUSIVE_PREF(例: pmc は a2/b2/b4/c2/c4/d3/d4x/a4x、society は a2x/b2x/b4/c2x/c4x/d3x/d4x/a4x)
(2b) 強化: baseUpgradeMax > 1 のとき、所有拠点(強化中でなく level < 上限)を 首都 → 係争地 → 自陣 の順に見て、
      supply ≥ cost × UPGRADE_SUPPLY_MARGIN なら 1 つだけ upgrade
(2c) 防御施設: 総数 < DEFENSE_LIMIT_PER_PLAYER かつ supply ≥ cost × DEFENSE_SUPPLY_MARGIN のとき、
      先に c3 済みで妨害塔が無ければ首都へ jammer、c1 済みで観測塔が無ければ 自分の係争地の拠点 → 橋I へ watchtower を各1。
      次に 種類 = 航空を見ていて a3 済みなら aa_site、それ以外 turret。首都 → 自チームの橋I → 自分が所有する係争地の拠点 の順に、
      空きがあり同じ種類が無いアンカーへ 1 基だけ build_defense
(3) 部隊: teamAttack = Σ 自チーム部隊の attack(係数込み)、teamHp = Σ hp
      defend = findIntruder(自チームの拠点・渡河点端点から radius + 320 以内の敵。首都優先、次に近さ。
               threat = その敵から 200 以内の敵の対地ダメージ dmg.ground × 係数 の合計)
      target = pickTarget(到達可能で勝てそうな未所有拠点。終盤は大拠点 > 中盤以降は中規模 > その他、同順位は首都から近い順)
      task   = buildTask(target が無いか now ≥ 3分 なら自陣の橋I。終盤は c1 済みで隣接境界の橋II(近い方)。
               橋Iを他チームに奪われていて c3 済みなら索道I。研究・補給(cost 以上。自チーム建設中なら不要)・端点への到達可能性を満たすもの)
      task の端点に自部隊が隣接していて builder 未設定なら build
      各部隊(retreat 態勢で退避中 `retreating` の部隊は Match に任せて指示しない):
        哨戒艇 → 川から到達できる最も近い敵の渡河点(無ければ港で待機)
        defend があり teamAttack ≥ threat → 敵の位置(到着半径 = 射程 × 0.7)
        補給線が切れた自拠点があれば → その拠点に最も近い他チーム所有の渡河点の端点(奪還)
        task(攻撃ヘリ以外) → 端点(到着半径 = radius + 60 − 15)
        target → 拠点中心(到着半径 = radius × 0.5)
        それ以外 → 首都
        到着済み、または同じ目的地(30 以内)へ移動中なら指示しない
(5) 合図: 大拠点が出現した最初の思考で他チーム1つにランダムで ally。
      味方が2人以上のとき 60 秒おきに 50% で attack(target の位置)
```

**「勝てそう」**(`winnable(b)`、30章の `forecast` を使う):

```
attackers = 自チームの部隊(哨戒艇を除く)を squadCombatant(type, hp, mods.attack)。敵側の NPC文明の部隊は squadCombatant(type, hp, npcMul)
defenders = [中立で guardHp>0 なら npcCombatant("守備", guardHp, guardAttack)]
          + [b から radius + 300 以内の敵ユニット]
          + [b に付いた他チームの砲座・対空陣地(kind structure, dmg = DEFENSES[kind].dmg)]
          + [b 自身: level ≥ 2 なら npcCombatant("砲座", hp, turretAttack × turret, "structure")、それ以外 structureCombatant(hp)]
r = forecast(attackers, defenders);  勝てそう = r.win かつ r.attackerLoss ≤ MAX_ATTACKER_LOSS
```

**定数**(bot.ts): `DEFEND_RANGE 320, TEAM_SIGNAL_INTERVAL_MS 60000, BRIDGE_DEADLINE_MS 180000, UPGRADE_SUPPLY_MARGIN 2, DEFENSE_SUPPLY_MARGIN 3, MAX_ATTACKER_LOSS 0.6`。退避の閾値は態勢の定数(23章)。思考間隔は `MATCH.botThinkMs = 2000`。

**計算例**: pmc 装甲強襲 3 体(各 HP 300、対地 33.6/秒、対構造物 22.4/秒)で中規模拠点(守備 HP 900・攻撃 40、拠点 HP 900): forecast では守備(40/秒)が先頭の 1 体を 8 秒で倒し(300 被弾)、残り 2 体が 10 秒目に守備を倒す(2 体目は 80 被弾)。その後 2 体で拠点を `900 / 44.8 ≈ 21 秒` で 0 に → win、損耗 `380 / 900 ≈ 0.42 ≤ 0.6` で選ぶ。装甲強襲 1 体なら守備に `30 秒 × 40 = 1200 > 300` で先に倒れ win=false。

## 17. スコアと MVP

**集計の契機**(`ScoreEntry`、プレイヤーごと):

| 項目 | 契機 |
| --- | --- |
| captures | 首都以外の拠点を制圧した部隊のオーナー(NPC拠点の制圧、NPC本拠の陥落も数える。NPC文明の制圧は数えない) |
| ticketsDealt | 敵部隊を撃破したときの損失額(8 × factor)、首都を落としたときの実損失 `min(tickets, 150)` |
| npcKills | NPC文明の部隊を撃破 |
| squadsLost | 自分の部隊が撃破された(首都陥落で失った部隊は数えない。撃破者が守備NPC・NPC文明でも数える) |
| squadsKilled | 敵部隊を撃破 |
| hqFalls | 敵首都を落とした |
| promotions | 自分の部隊が昇格した段数の合計(32章) |
| veterans | 試合終了時に生存している rank == VETERANCY_MAX_RANK の部隊数(終了時に集計) |

**MVP**(終了時):

```
mvpScore = captures × 3 + ticketsDealt / 20 + npcKills × 2 + squadsKilled + promotions
mvp = mvpScore が最大のプレイヤー(同点は先に登録された方)
maxScore = max(1, max mvpScore)
contributionBonus(p) = (p == mvp) ? RATING.contributionMax : round(mvpScore(p) / maxScore × RATING.contributionMax)
```

**定数**: `RATING.contributionMax = 5`。

**計算例**: captures 6、ticketsDealt 120、npcKills 2、squadsKilled 3 → `18 + 6 + 4 + 3 = 31`。MVP のスコアが 40 なら貢献ボーナスは `round(31/40 × 5) = 4`。

## 18. 報酬・pick の検証・試合無効化

### 18.1 報酬(rewards.ts `computeRewards`)

**入力**: Profile、使った文明、順位 `rank`(0 始まり)、貢献ボーナス、MVP か、ScoreEntry、日付 `today`。

**XP とレベル**:

```
contribution = min(CIV_XP.contributionCap, captures × 2 + ticketsDealt / 10 + npcKills × 2)
xp = round(CIV_XP.base + CIV_XP.byRank[rank] + contribution)
totalXp = civs[civ].xp + xp
levelAfter = civLevelFor(totalXp)   … CIV_LEVEL_XP の index+1 で、totalXp ≥ 閾値 を満たす最大
開放: l = levelBefore+1 .. levelAfter について PERMANENT_UNLOCKS[l] と CIV_STORY[civ][l−1]
```

**ドロップ**:

```
dropsToday = (dropsDate == today) ? dropsToday : 0
count = max(0, min(DROPS.perMatch[pass] + (MVP ? DROPS.contributionBonus : 0), DROPS.dailyCap[pass] − dropsToday))
count 回: 使い切りアドオンを rarityWeight で重み付き抽選
  在庫 ≥ DROPS.stackCap なら捨てる(drops に含めないが count には数える)。それ以外は在庫 +1
dropsToday += count; dropsRemainingToday = max(0, dailyCap − dropsToday)
```

**レート**(`ratingDeltaFor`):

```
delta = max(−RATING.maxLossPerMatch, RATING.byRank[rank] + clamp(round(bonus), 0, RATING.contributionMax))
rating += delta; matches += 1; rank == 0 なら wins += 1; civMatches[civ] += 1
```

**称号**(初めて得たものだけ `titlesGained` に): `matches == 1` → firstMatch、`勝利かつ wins == 1` → firstWin、MVP → mvp、`matches ≥ 10` → veteran10。

**定数**: `CIV_XP = { base 40, byRank [40, 20, 10, 0], contributionCap 50 }`、`CIV_LEVEL_XP = [0, 100, 250, 450, 700, 1000]`、`PERMANENT_UNLOCKS = {1: p_logistics, 2: p_scouts, 3: p_armor, 4: p_optics, 5: p_reveal}`、`DROPS = { perMatch {none 1, standard 2, premium 3}, dailyCap {none 3, standard 6, premium 9}, contributionBonus 1, stackCap 10, rarityWeight {1: 60, 2: 30, 3: 10} }`、`RATING = { initial 1000, byRank [20, 0, −15, −25], contributionMax 5, maxLossPerMatch 25 }`、`TITLES`、`DAY_OFFSET_MINUTES = 540`(`todayString` は UTC+9 で日替わり)。

**計算例**: 2位(rank 1)、captures 6、ticketsDealt 120、npcKills 2、貢献ボーナス 4、MVP でない、pass standard、今日のドロップ消化 5、文明 XP 180(Lv2):

```
contribution = min(50, 12 + 12 + 4) = 28;  xp = 40 + 20 + 28 = 88;  totalXp = 268 → Lv3(≥250)
開放: PERMANENT_UNLOCKS[3] = p_armor、物語 CIV_STORY[civ][2]
drops: count = max(0, min(2 + 0, 6 − 5)) = 1。使い切りは c_supply(30) / c_rally(30) / c_sabotage(10) の重み → 確率 3/7, 3/7, 1/7
rating: max(−25, 0 + 4) = +4
```

4位相当(rank 3)で貢献 0 なら `max(−25, −25 + 0) = −25`。

### 18.2 pick の検証(lobby.ts `validatePick`)

```
addons の数 ≤ ADDON_SLOTS、重複なし
永続: unlockedPermanents(profile.civs[civ].level) に含まれること(レベル l 以下の PERMANENT_UNLOCKS の和)
使い切り: 在庫 > 0、かつ件数 ≤ CONSUMABLE_SLOT_LIMIT
違反は error を返し pick を受理しない。未 pick は時間切れ時にランダム(開放済みの永続のみ)
試合開始時に使い切りを在庫から消費(consumeConsumables)。在庫が消えていたものは外す
```

**定数**: `ADDON_SLOTS = 4`、`CONSUMABLE_SLOT_LIMIT = 2`。

### 18.3 試合中のアドオン発動(`useAddon`)

```
条件: 枠が存在、active を持つ、未使用、クールダウン外
reveal_map → revealUntilMs = now + MATCH.revealMs
emergency_supply → supply += 250
rally_heal → 自分の全部隊 hp = min(maxHp, hp + maxHp × 0.4)
sabotage_bleed{toTeam} → teams[toTeam].sabotageUntilMs = now + MATCH.sabotageMs; 自分の supplyHalfUntilMs = 同じ
oneShot なら used = true
```

### 18.4 試合無効化と返却

```
人間全員が切断した内部時刻 disconnectedSinceMs を記録(誰かが戻れば消す)
毎 tick: now < 3分 なら即、または now − disconnectedSinceMs ≥ 60秒 で abort
abort: result を作らず aborted = true。報酬なし、プロフィールの戦績は変えない
lobby: 開始時に消費した使い切りを refundConsumables で在庫へ戻す(stackCap まで)。再接続時は lobby{idle} を返す
```

## 20. 研究(予約列・完了・定期可視)

**目的**: 研究を時間のかかる逐次処理にし、前提・排他・予約列を扱う。

**入力**: `research{nodeId}` / `research_cancel{nodeId}`、`RESEARCH_TREES[civ]`、プレイヤーの `research, researched, researching, researchQueue`。

**開始と予約**(`Match.research`):

```
node = researchNode(civ, nodeId); 無ければ error
canResearch(civ, nodeId, researched):
  研究済み → 不可 / excludes の相手が研究済み → 不可(排他)
  tier > 1 なら 同じ branch の tier−1 のいずれかが研究済み であること(前提)
researching が同じ id → "研究中です"; researchQueue に含む → "予約済みです"
researching が無く research ≥ node.cost → 即開始(startResearch)
それ以外 → researchQueue.length ≥ RESEARCH_QUEUE_LIMIT なら error、でなければ末尾に追加
startResearch: research −= cost; researching = { nodeId, startedAtMs: now, readyAtMs: now + node.timeMs }
研究時間に係数は掛からない。コストは開始時にだけ払う
```

**取り消し**(`researchCancel`): 予約列から外す。研究中のノードは中止できない(error)。

**完了と列の消化**(`updateResearch`、毎 tick、プレイヤーごと):

```
researching があり now ≥ readyAtMs:
  researched に追加; refreshMods(2章); イベント research_done(本人)
  node.effect.revealIntervalMs があれば nextRevealAtMs = now + revealIntervalMs
researching が無い間、列の先頭 id について:
  canResearch が不可(前提が崩れた・排他の相手を取った) → 列から外して次へ
  research < cost → 待つ(列はそのまま)
  それ以外 → 列から外して startResearch
定期可視: nextRevealAtMs があり now ≥ nextRevealAtMs:
  revealUntilMs = max(revealUntilMs, now + MATCH.revealMs); nextRevealAtMs += unlocks.revealIntervalMs
```

**定数**: `RESEARCH_QUEUE_LIMIT = 3`。コスト/時間: 段1 60 / 30s(工兵 d1 は 90 / 40s)、段2 120 / 45s(d2 は 90 / 40s)、段3 180 / 60s、段4 300 / 90s(工兵 d4/d4x は 240 / 75s)。`c4` 電子戦 `revealIntervalMs 300000`(foundation の c4「全域観測」は 240000)、`MATCH.revealMs = 10000`。

**計算例**: 研究ポイント 200 で a1(60)を開始 → 残り 140、30 秒後に完了して `attack ×1.1`(pmc 版は 1.15)。続けて a2(120)と a2x を指示すると a2 は列へ(研究中なら)か即開始、a2x は a2 が研究済みになった時点で「排他」。a3 を列に入れたままポイントが 180 未満なら、列の先頭で貯まるまで待つ。c4 を取ると完了の 5 分後から 10 秒間全域が見え、以後 5 分ごと。

## 21. 維持費

**目的**: 部隊数に応じて補給を継続的に消費させる。

**式**(`updateIncome` の末尾、毎 tick、プレイヤーごと):

```
upkeep = Σ_{s: 自分の部隊(生産中は含めない、NPC文明は対象外)} SQUADS[s.type].upkeepPerSec × mods.upkeep
priv.upkeepPerSec = upkeep
supply = max(0, supply − upkeep × dt)
```

補給が 0 のときは減らないだけで、生産・建設・強化ができなくなる。収入と維持費は同じ tick で順に処理される(収入 → 維持費)。

**定数**: `SQUADS.*.upkeepPerSec` = assault 2.4 / scout 1.2 / siege 3.6。研究 b2x「維持費削減」`upkeep 0.7`。

**計算例**: 強襲 3・斥候 1 を持つ pmc(upkeep 係数 1): `upkeep = 2.4×3 + 1.2 = 8.4/秒`。首都 Lv1 + 小拠点 3(補給 10 × 1.1 = 11/秒)なら純増は 2.6/秒。b2x を取ると `8.4 × 0.7 = 5.88/秒`。

## 22. 拠点の強化と砲座

**目的**: 補給を払って所有拠点の収入・耐久を上げ、砲座で自衛させる。

**開始**(`upgrade{baseId}`):

```
条件(順に判定、違反は error):
  base が active かつ ownerPlayer == 自分(首都は自分の首都) / 自分が fallen でない / 強化中でない
  level < unlocks.baseUpgradeMax(研究 b3 で 2、b4x で 3。超えていれば "研究が必要です"、Lv3 到達なら "これ以上強化できません")
  spec = BASE_UPGRADES[tier][level](次のレベルの仕様); supply ≥ spec.cost
supply −= spec.cost
upgrading = { toLevel: level + 1, readyAtMs: now + spec.timeMs / mods.buildSpeed }
```

**完了**(`updateUpgrades`、毎 tick):

```
upgrading があり now ≥ readyAtMs:
  (active でない、または中立なら取り消すだけ)
  level = toLevel; maxHp = baseMaxHp(b); hp は比率を維持; イベント base_upgraded(所有チーム)
baseMaxHp(b) = round(BASES[tier].hp × mods(ownerPlayer).baseHp × BASE_UPGRADES[tier][level − 1].hp)
```

**効果**:
- 収入: 3章の `lv = BASE_UPGRADES[tier][level − 1].income` を補給・研究の両方に掛ける。
- 耐久: 上の `baseMaxHp`。研究で `baseHp` が変わったときも同じ式で再計算。
- 砲座(6章): `level ≥ 2` の所有拠点は毎 tick、中心から `BASE_UPGRADE_RANGE` 以内で最も近い敵部隊(他チームと NPC文明)1体に `turretAttack × mods(ownerPlayer).turret × dt`。攻撃を受けた部隊は `engaged`。首都の保護期間や守備NPCとは独立。

**リセット**: 制圧・中立化・首都陥落・再建で `level = 1`、`upgrading` 解除(7章・8章)。

**定数**(`BASE_UPGRADES[tier]`、index = level−1):

| tier | Lv2 cost / timeMs / income / hp / turret | Lv3 cost / timeMs / income / hp / turret |
| --- | --- | --- |
| hq | 600 / 60000 / 1.25 / 1.3 / 25 | 1200 / 90000 / 1.5 / 1.6 / 50 |
| small | 300 / 45000 / 1.3 / 1.3 / 12 | 600 / 75000 / 1.6 / 1.6 / 25 |
| mid | 500 / 60000 / 1.3 / 1.3 / 20 | 1000 / 90000 / 1.6 / 1.6 / 40 |
| grand | 800 / 60000 / 1.3 / 1.3 / 30 | 1600 / 90000 / 1.6 / 1.6 / 60 |

`BASE_UPGRADE_RANGE = 160`。研究 b4x「要塞化」`turret 1.5`、d4x「工兵隊」`buildSpeed 2`。

**計算例**: pmc(baseHp 1)が b3(`baseHp 1.2`)を取って首都を Lv2 に: 補給 −600、60 秒後に `maxHp = round(1500 × 1.2 × 1.3) = 2340`(HP 1800/1800 なら 2340/2340)、補給収入 `4 × 1.25 = 5/秒`。砲座は 160 以内の敵部隊に 25/秒(1 tick 2.5)。b4x まで取れば Lv3 で `turret 50 × 1.5 = 75/秒`。

## 23. 態勢と集結点

**目的**: 部隊ごとの自動行動(追跡・待機・退避)と、生産部隊の集合地点。

**入力**: `stance{squadId, stance}`(自分の部隊のみ)、`rally{pos?}`。生産時の態勢は aggressive。

**毎 tick**(`updateStances`、移動の前、プレイヤー部隊ごと):

```
retreat:
  !retreating かつ hp < maxHp × RETREAT_HP_RATIO かつ 自分の首都が active
    → retreating = true; plan(s, 首都の中心)        … 10章の回復を受ける
  retreating かつ hp ≥ maxHp × RETREAT_RECOVER_RATIO
    → retreating = false; rally があれば plan(s, rally)、無ければ target を消して待機
  (退避中もプレイヤーの move は受け付ける。態勢を変えると retreating は解除)
aggressive:
  target が無く now ≥ nextChaseAtMs のとき(CHASE_INTERVAL_MS ごと):
    自分の視界 squadVision(s) 内で、射程 range より遠く、隠密を考慮した距離(d ≤ vision × stealthFactor(o))にいる
    最も近い敵ユニット(他チームの部隊・NPC文明の部隊)へ plan(s, o.pos)
    (目的地がある間は追わない。到着後・待機中のみ。射程内の敵には移動せず6章で撃つ)
hold:
  何もしない(指示された移動だけ行い、射程内だけ撃つ)
```

**集結点**(`rally`): `priv.rally = pos`(マップ内にクランプ)。以後に生産が完了した部隊は出現直後に `plan(s, rally)`。省略で解除。retreat の復帰先にも使う。

**定数**: `RETREAT_HP_RATIO = 0.4`、`RETREAT_RECOVER_RATIO = 0.9`、`CHASE_INTERVAL_MS = 1000`(match.ts)。

**計算例**: 強襲(maxHp 300)が retreat 態勢で HP 110(36.7%)になった tick で首都へ向かう。首都の半径+60 に入ると 10章の回復 12/秒で、`270` に達するまで約 13 秒。集結点が首都から 300 の地点なら、回復後にそこへ戻る(110/秒で約 2.7 秒)。aggressive の斥候(視界 420)は、停止中に 300 離れた敵を見つけると 1 秒以内に追い始め、射程 100 に入ると移動せず撃つ。

## 24. 構成の可変(陣営数・人数)

**目的**: 1試合ごとに陣営数 N と人数 perTeam を変えられるようにする。

**入力**: `queue{config}` / `start_with_bots{config}` の `Partial<MatchConfig>`。

**正規化**(`normalizeMatchConfig`):

```
teams   = clamp(floor(config.teams ?? TEAM_COUNT), MIN_TEAMS, MAX_TEAMS)
perTeam = clamp(floor(config.perTeam ?? PLAYERS_PER_TEAM), 1, MAX_PLAYERS_PER_TEAM)
```

**ロビー**(lobby.ts): キューは `${teams}x${perTeam}` ごとに別。人数が `teams × perTeam` に達すると選択フェーズ。ボット補完はキューの人間を先頭から `i % teams` でチームに配り、残りをボット(`BOT-{TEAM_LABELS[team]}{floor(i / teams) + 1}`)。`LobbyState.config`、`MatchStartPayload.config`。

**試合内で N・perTeam に依存するもの**:

| 項目 | 依存 |
| --- | --- |
| マップ(15章) | 首都角度 360°/N、チーム内 ±15° の等間隔、自陣小拠点 perTeam×2、境界川・b2/b3/r2 は N 本 |
| チーム(11〜12章) | `teams[]` は N 個。bleed の「他チーム平均」、順位、脱落判定は N で動く |
| 部隊損失(11章) | `ticketLossPerSquad × ticketLossFactor / perTeam`(チーム合計 `startTickets` は人数で変えない) |
| 合図・根回しの宛先 | `0 ≤ toTeam < N` かつ自チーム以外 |
| 収入(3章) | 拠点ごとの ownerPlayer に入るので、チーム内で拠点を取った人に偏る |
| ボット(16章) | 境界の橋II は `b2_t{team}` と `b2_t{(team + N − 1) % N}` |

**定数**: `TEAM_COUNT = 3`、`PLAYERS_PER_TEAM = 1`(既定)、`MIN_TEAMS = 2`、`MAX_TEAMS = 4`、`MAX_PLAYERS_PER_TEAM = 3`、`TEAM_COLORS / TEAM_SYMBOLS / TEAM_LABELS` は 4 陣営分。

**計算例**: `{teams: 4, perTeam: 3}` → 12 人、首都は 90° 間隔で各陣営 3 つ(±15°)、自陣小拠点 6 × 4 + 島 4 = 28、中規模 4、渡河点 20。強襲を 1 体失うと `8 × 1.0 / 3 ≈ 2.67` チケット。`{teams: 2, perTeam: 1}` → 境界川は 2 本(首都角 ±90°)、渡河点 10。

## 25. 部隊種と攻撃可否

**目的**: 陸上・航空・水上の部隊と構造物のあいだで「誰が誰を撃てるか」を行列で決める。

**入力**: `SQUADS[type].domain`(ground/air/naval)、`SQUADS[type].dmg[kind]`(kind = ground/air/naval/structure)、`mods.attack`。

**式**(`unitDmg(u, kind)`、`unitKind(u)`):

```
unitKind(u) = SQUADS[u.type].domain                               … NPC文明の部隊も部隊種どおり
unitDmg(u, kind):
  NPC文明:  SQUADS[u.type].dmg[kind] × npcMul(成長倍率。13章)
  部隊:     SQUADS[u.type].dmg[kind] × mods(owner).attack          … 0 なら撃てない
守備NPC・拠点の砲座: 単一の攻撃値 × (相手が air なら NPC_AIR_FACTOR)。構造物は撃たない
防御施設: DEFENSES[kind].dmg[相手の種類](0 なら撃てない)
```

**定数**(`SQUADS`、dmg = ground / air / naval / structure):

| type | domain | dmg | range | speed | hp | cost | upkeep | canCapture | research |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| assault 装甲強襲 | ground | 30 / 8 / 15 / 20 | 120 | 110 | 300 | 120 | 2.4 | ○ | なし |
| scout 偵察 | ground | 12 / 4 / 5 / 5 | 100 | 190 | 120 | 60 | 1.2 | ○ | なし |
| siege 自走砲 | ground | 15 / 0 / 10 / 60 | 150 | 75 | 260 | 180 | 3.6 | ○ | a2 |
| aa 対空車両 | ground | 8 / 60 / 8 / 5 | 200 | 100 | 240 | 140 | 2.4 | ○ | a3 |
| gunship 攻撃ヘリ | air | 35 / 10 / 30 / 15 | 140 | 170 | 220 | 220 | 4.0 | × | a4 |
| boat 哨戒艇 | naval | 25 / 15 / 30 / 35 | 180 | 120 | 320 | 200 | 3.0 | × | d4 |

`NPC_AIR_FACTOR = 0.5`。`DEFENSES.turret.dmg = 25/0/20/0`、`aa_site = 0/50/0/0`、`minefield = 120/0/0/0`。

**計算例**: pmc(`attack 1.12`)の自走砲は敵の攻撃ヘリを撃てない(`dmg.air 0`)が、ヘリは自走砲に `35 × 係数 /秒`。同じ pmc の対空車両はヘリに `60 × 1.12 = 67.2/秒` で、HP 220 のヘリを約 3.3 秒で落とす。守備NPC(小拠点 10/秒)はヘリに `10 × 0.5 = 5/秒`。

## 26. 対象選択と制圧の可否

**目的**: 複数の候補があるときに何を撃つかを決め、制圧できる部隊を限定する。

**式**(6章の擬似コードの要約):

```
候補 = 射程内で unitDmg(s, 種類) > 0 のもの
優先: 1) 敵部隊 → 2) 守備NPC → 3) 防御施設(砲座・対空陣地) → 4) 拠点・渡河点
同じ順位では距離(構造物は半径を引く)が最も近いもの
対空車両(aa): 1) で射程内に航空がいれば必ず航空(陸上が近くても)
NPC文明: 1) 他チームの部隊、2) 中立拠点の守備NPC、4) NPC所有でない拠点(渡河点・防御施設は撃たない)
```

**制圧の可否**(`canCapture`):

```
canCapture(u) = SQUADS[u.type].canCapture(陸上の4種。NPC文明の陸上部隊も制圧できる)
拠点: hp ≤ 0 になった攻撃が canCapture でなければ hp = 0 のまま所有を変えない(lastHitMs は更新するので回復もしない)。
      その後、陸上部隊の一撃で 首都なら陥落、それ以外は制圧
渡河点: hp ≤ 0 になった攻撃が canCapture でなければ 予定地へ戻す(resetCrossing、crossing_demolished を旧所有チームへ)
```

**計算例**: 攻撃ヘリ 1 体が中立の小拠点を攻める: 守備 200 を `35/秒`(対地)で約 5.7 秒、拠点 HP 400 を `15/秒`(対構造物)で約 27 秒かけて 0 にするが、owner は −1 のまま。あとから装甲強襲が射程に入った最初の tick に制圧され、`ownerPlayer` は強襲のオーナー。哨戒艇が敵の橋I(HP 500)を `35/秒` で 0 にすると、橋は未建設の予定地に戻る。

## 27. 航空・水上の移動と港

**目的**: 領域ごとの通行判定を分ける。

**式**(`plan`、`passPredicate`、`reachable`):

```
passPredicate(team, type) = passableForDomain(terrain, domain, 陸上なら passableFor(team, type))
  ground: land ∪ 自チーム所有の渡河点セル(索道は自走砲不可)
  air:    全セル
  naval:  terrain.cells[idx] == river のセルのみ(橋のセルも川なので通れる)
plan(s, goal):
  air   → path = [goal], unreachable = false(経路探索なし、直線)
  他    → findPath(terrain, pos, goal, passPredicate)(5章と同じ。水上は川から出られない)
reachable(team, type, from, to) = air なら常に true、他は findPath の reachable(セル単位でキャッシュ)
```

**港**(`findDock`): 首都の中心から `DOCK_SEARCH_RANGE` 以内で最も近い川のセル中心。無ければ `dock = undefined` で水上部隊は生産できない。再建時に再計算。水上部隊は港のセル中心に出現(陸上・航空は首都の周囲 40)。

**定数**: `DOCK_SEARCH_RANGE = 600`(match.ts)。速度は 25章の表(航空 170、水上 120)。

**計算例**: 首都から 1150 離れた中央の島まで、攻撃ヘリは橋がなくても直線で `≈ 1150 / 170 ≈ 6.8 秒`。哨戒艇は港から環状の川に沿って進み、陸上の目的地を指示されると最も近い川のセルで止まり `unreachable = true`。

## 28. 防御施設

**目的**: 所有する拠点・渡河点に砲座・対空陣地・地雷原を付ける。

**設置**(`buildDefense{kind, anchorType, anchorId}`、順に判定):

```
spec = DEFENSES[kind]; 自分が fallen でない; spec.anchors に anchorType が含まれる; spec.research があれば研究済み
base:     active かつ ownerPlayer == 自分、強化中でない
crossing: built かつ owner == 自チーム、解体中でない
自分の施設数(建設中含む) < DEFENSE_LIMIT_PER_PLAYER; アンカーの使用スロット数 < DEFENSE_SLOTS_PER_ANCHOR
supply ≥ spec.cost → supply −= cost
位置: base は中心から角度 0°(slot 0)/180°(slot 1)に DEFENSE_OFFSET、crossing は ends[slot] から外側(pos→end の向き)に DEFENSE_OFFSET
readyAtMs = now + spec.buildMs / mods.buildSpeed; hp = maxHp = spec.hp(建設中も攻撃を受ける); armed = false
```

**完了と消滅**(`updateDefenses`、毎 tick):

```
アンカーが無い/active でない/ownerPlayer が変わった(渡河点: built でない/owner が変わった) → 施設を消す(イベントなし)
readyAtMs ≤ now → 完成: readyAtMs を消す; 地雷原は armed = true; イベント defense_built(所有チーム)
priv.defenseCount = 自分の施設数
```

**攻撃**(6章の最後、完成済みのみ):

```
砲座・対空陣地: 射程 spec.range 内で spec.dmg[相手の種類] > 0 の最も近い敵部隊(NPC文明含む)に
                spec.dmg[種類] × (アンカーの補給線が切れていれば SUPPLY_LINE.turretFactor) × dt
地雷原: armed かつ射程 70 内に敵の陸上部隊が入った tick に、最も近い1体へ dmg.ground を一撃で与えて消滅。
        イベント mine_triggered(所有チームと被害チーム)
```

**耐久**: 敵部隊は 26章の優先 3) で `dmg.structure` を与える。`hp ≤ 0` で消滅し `defense_destroyed`(所有チーム)。地雷原は敵に見えないので攻撃対象にならない。

**可視**(14章): 自チームの施設は常に。他チームの地雷原は見えない。それ以外は施設の位置か、アンカー(拠点/渡河点)がスナップショットに含まれていれば見える。

**観測塔・妨害塔**(攻撃しない施設。設置・耐久・破壊・アンカー喪失は上と同じ):

```
watchtower(研究 c1): 完成後、所有チームの視界円に (pos, vision 500) を追加(14章)。補給線が切れていても機能する。
                    敵の妨害塔の圏内(jamFactorAt(pos, team) < 1)にあると円ごと無効
jammer(研究 c3):     完成後、jamRadius 350 内で
  (a) 敵チームの視界源(部隊・拠点・渡河点)の半径 × jamFactor 0.5(複数の妨害塔が重なれば乗算)
  (b) 圏内の自チーム部隊は、敵の視界半径 × jamFactor の距離でしか見えない(隠密・煙幕と重なるときは小さい方)
  (c) 圏内の敵の観測塔は無効
  妨害塔どうしは影響しない。作戦指令の電波妨害(31章)とは乗算
```

**定数**: `DEFENSES` = turret {cost 150, buildMs 30000, hp 300, range 170}、aa_site {150, 30000, 250, 220, research a3}、minefield {100, 20000, hp 1, range 70}、watchtower {120, 25000, 200, vision 500, research c1}、jammer {180, 35000, 220, jamRadius 350, jamFactor 0.5, research c3}。`DEFENSE_SLOTS_PER_ANCHOR = 2`、`DEFENSE_LIMIT_PER_PLAYER = 6`、`DEFENSE_OFFSET = 70`、`DEFENSE_RADIUS = 20`(match.ts)。

**計算例**: 首都に妨害塔を置くと、圏内 350 に入った敵の偵察(視界 420)は 210 しか見えず、電波妨害中なら 105。圏内にいる自分の装甲強襲は、圏外の敵偵察から 210 まで近づかれないと見つからない。島の拠点の観測塔は補給線が切れていても半径 500 を照らす。首都に砲座を置くと 30 秒(d4x なら 15 秒)で完成し、首都中心から 70 の位置から半径 170 内の敵陸上部隊に 25/秒。攻撃ヘリには 0 なので、対空陣地(50/秒、射程 220)を 2 つ目のスロットに置く。敵の自走砲(対構造物 60/秒)が砲座を狙うと HP 300 は 5 秒で壊れる。

## 29. 補給線

**目的**: 首都から陸路でつながっていない拠点の価値を下げる。

**式**(`updateSupplyLines`、`supplyDirty` のときだけ再計算):

```
reach(p) = p の首都セルから 8近傍(角抜け禁止)で到達できるセルの集合。通行 = land ∪ 自チーム所有の渡河点(索道も可)。
           首都が active でない(陥落中)なら空
b.connected = (tier == hq) または (owner < 0) または reach(ownerPlayer) に b のセルが含まれる
渡河点 c の connected = reach(ownerPlayer) に ends[0] か ends[1] のセルが含まれる(ownerPlayer が無ければ true)
再計算の契機: 渡河点の状態変化(onCrossingsChanged)、拠点の制圧/中立化、首都の陥落/再建
```

**効果**:

| 対象 | 切れているとき |
| --- | --- |
| 収入(3章) | `× SUPPLY_LINE.incomeFactor`(補給・研究とも) |
| 拠点の回復(7章) | `× regenFactor`(= 0 なので回復しない) |
| 強化拠点の砲座(22章)と防御施設の攻撃(28章) | `× turretFactor` |
| 渡河点の回復(9章) | 所有者の首都から到達できなければ回復しない |

**定数**: `SUPPLY_LINE = { incomeFactor 0.5, regenFactor 0, turretFactor 0.5 }`。

**計算例**: 橋I を渡って島の小拠点(Lv1、補給 2/秒)を取った pmc は `2 × 1.1 = 2.2/秒` を得るが、橋I を奪われると島への陸路が無くなり `connected = false` → 補給 `1.1/秒`、HP は回復せず、Lv2 の砲座は 12 × 0.5 = 6/秒。奪い返すか別の渡河点を建てると次の tick で復帰する。

## 30. 戦闘予測(forecast)

**目的**: サーバー(ボット)とクライアント(ドラッグ時の表示)で同じ勝敗の見込みを出す。

**入力**: 攻撃側・防御側の `Combatant[]`(label, kind, hp, dmg)。防御側の並び順 = 攻撃を受ける順(守備NPC → 部隊 → 構造物)。

**擬似コード**(shared `forecast(attackers, defenders, maxSeconds = 180)`):

```
毎秒 t = 1..maxSeconds:
  各側の生存者はそれぞれ、相手側で「最初に並んでいる撃てる部隊(kind ≠ structure かつ dmg[kind] > 0)」、
  無ければ「最初の構造物(dmg.structure > 0 のとき)」に dmg[kind] を与える(同時適用)
  防御側が全滅 → win=true, seconds=t, attackerLoss = 1 − 攻撃側の残りHP / 初期HP
  攻撃側が全滅、または撃てる相手がいない → win=false
上限まで決着しなければ win=false(seconds なし)
```

生成ヘルパ: `squadCombatant(type, hp, attackMul)`(部隊。dmg は行列 × 係数)、`npcCombatant(label, hp, attack, kind)`(全領域 attack、対空 ×NPC_AIR_FACTOR、構造物 0)、`structureCombatant(label, hp)`(撃たない)。

**ボット**: 16章の `winnable` が使う。攻撃側は自チームの部隊(哨戒艇を除く)、防御側は 守備NPC → 半径+300 内の敵ユニット → その拠点の砲座・対空陣地 → 拠点(Lv2 以上なら砲座として npcCombatant、kind structure)。`win` かつ `attackerLoss ≤ 0.6` で目標にする。

**計算例**: 攻撃側 = 装甲強襲 2 体(HP 300、dmg 30/8/15/20)、防御側 = 対空車両 1 体(HP 240、dmg 8/60/8/5)+ 小拠点(HP 120): 毎秒 強襲 2 体が対空に 60、対空が先頭の強襲に 8 → 4 秒で対空が倒れ(先頭は 268)、その後 2 体で拠点に 40/秒 → 3 秒。`win=true, seconds=7, attackerLoss = 32/600 ≈ 0.05`。防御側に攻撃ヘリ(HP 220、対地 35)が加わると、強襲の対空ダメージは 8 × 2 = 16/秒で 14 秒かかり、その間に先頭が 35 × 14 = 490 を受けて 1 体脱落 → 損耗が上がる。

## 31. 指導者の作戦指令

**目的**: 文明ごとに 1 種類の、クールダウン付きの能動効果。

**入力**: `leader_command{pos?, toTeam?}`、`LEADER_COMMANDS[civ]`、プレイヤーの `commandReadyAtMs`。

**条件と実行**(`leaderCommand`):

```
spec = LEADER_COMMANDS[civ]; fallen でない; now ≥ commandReadyAtMs
needsPos なら pos(マップ内にクランプ)、needsTeam なら 0 ≤ toTeam < teams かつ 自チーム以外
効果を適用(下表)
commandReadyAtMs = now + spec.cooldownMs; commandActiveUntilMs = now + (spec.durationMs ?? 0)
イベント leader_command: 自チームへは pos 込み、他チームへは pos を伏せる(artillery だけは pos を見せる)。toTeam は needsTeam のときのみ
```

| 文明 / id | 効果(power, radius, durationMs) | 実装 |
| --- | --- | --- |
| pmc artillery | 150, 150, 5000 | 予約 `strikes` に積み、durationMs 後の tick(`updateStrikes`、移動の後・交戦の前)に着弾: 半径内の敵の陸上・水上部隊(航空は除く)に power、敵の拠点(半径を足す。中立と保護中の首都は除く)・渡河点・防御施設に `power × 2/3 = 100`。制圧できない仮想ユニット扱いなので構造物は 0 で止まる(渡河点は予定地へ戻る) |
| corp surge | 150, −, 30000 | `trainBoostUntilMs = now + 30000`: その間の train は `trainMs × trainTime × 0.5`。supply += 150 |
| society smoke | 0, 200, 20000 | 半径内の自分の部隊に `smokeUntilMs`。14章の `stealthFactor` が 0 になり、敵の視界円では見つからない(全域可視 `all` では見える) |
| agency bulwark | 0.5, −, 20000 | `team.bulwarkUntilMs`。自チームが所有する拠点・渡河点・防御施設への `damageBase / damageCrossing / damageDefense` のダメージ × 0.5 |
| foundation survey | 0, 500, 15000 | `team.surveys` に円を追加。14章の視界円に加わる(妨害の影響を受けない)ので範囲内の敵部隊・首都が見え、`updateReveals` で文明が判明 |
| intel jam | 0.5, −, 20000 | `teams[toTeam].jamUntilMs`。対象チームの視界円の半径 × 0.5(観測の円は除く) |

**定数**: `LEADER_COMMANDS`(cooldownMs: pmc 180000 / corp 180000 / society 150000 / agency 180000 / foundation 120000 / intel 180000)、`ARTILLERY_STRUCTURE_RATIO = 100/150`(match.ts)。

**ボットの使用条件**(16章の `command`、`commandReadyAtMs` 以降):

```
artillery: 敵の陸上・水上部隊のいずれかを中心に半径 150 内に敵が 3 体以上 → その位置
surge:     supply ≥ 300 かつ 部隊数 + 生産中 < squadLimit
smoke:     自部隊が交戦中かつ首都から 400 以上離れている → その部隊の位置
bulwark:   首都が contestedBy(攻撃中)
survey:    中盤以降に 1 回、マップ中心
jam:       中盤以降、順位が最も上の他チーム(未脱落)
```

**計算例**: pmc が 12:00 に敵の密集地点へ砲撃支援: 12:05 に半径 150 内の装甲強襲 3 体(HP 300)がそれぞれ 150 を受け、同じ範囲の敵の小拠点(Lv1, HP 400)は 300 に、敵の砲座(HP 300)は 200 に。次に使えるのは 15:00。agency の鉄壁中に自走砲(対構造物 67.2/秒)に首都を撃たれると `67.2 × 0.5 = 33.6/秒` に落ちる。

## 32. 部隊の練度

**目的**: 生き残って戦った部隊を強くし、失ったときの損失も大きくする。

**入力**: `SquadState.xp / rank`、`VETERANCY`、与ダメージ・とどめ・制圧・破壊のイベント。

**経験値の獲得**(`gainXp(u, amount)`。u が NPC・守備NPC・砲座・砲撃支援なら無視):

```
与ダメージ: 実際に減らした量 × xpPerDamage   … 敵部隊・守備NPC・拠点・渡河点・防御施設すべて(6章の各 damage*)
敵部隊のとどめ(NPC文明の部隊も同じ): SQUADS[相手の type].cost × xpPerKillCostFactor
拠点・渡河点の制圧/奪取/陥落のとどめ(canCapture の部隊が 0 にしたとき): + xpPerCapture
防御施設の破壊のとどめ: + xpPerStructureKill
```

**昇格**(同じ関数の中で):

```
rank' = veterancyRank(xp)(thresholds の index)。rank' > rank のとき:
  promotions += rank' − rank(一度に複数段上がれば段数ぶん)
  rank = rank'; maxHp = squadMaxHp(type, p, rank)(比率維持で hp も更新)
  イベント squad_promoted { squadId, slot, rank }(自チーム)
```

**係数**(すべて 2章の係数に乗算):

```
攻撃  unitDmg(u, kind) = SQUADS[type].dmg[kind] × mods.attack × (1 + attackPerRank × rank)
耐久  squadMaxHp(type, p, rank) = round(SQUADS[type].hp × mods.hp × (1 + hpPerRank × rank))   … 研究で mods.hp が変わったときも rank 込みで再計算
視界  squadVision(s) = SQUADS[type].vision × mods.vision × (scout なら scoutVision) × (1 + visionPerRank × rank)
損失  チケット = ticketLossPerSquad × ticketLossFactor × (1 + ticketPerRank × rank) / perTeam(11章)
```

**その他**: 首都陥落で失う半数は 段階 → 経験値 の低い方から(8章)。ボット/AI代行の部隊は rank ≥ 2 で retreat の退避しきい値が 0.4 → 0.5(23章の `VET_RETREAT_HP_RATIO`)。戦闘予測(30章)はボット側で `mods.attack × (1 + attackPerRank × rank)` を攻撃係数に使う。スナップショットの `xp` は四捨五入。

**定数**: `VETERANCY = { labels [新兵, 熟練, 精鋭, 古参], thresholds [0, 60, 150, 300], attackPerRank 0.08, hpPerRank 0.08, visionPerRank 0.05, ticketPerRank 0.1, xpPerKillCostFactor 0.25, xpPerDamage 0.02, xpPerCapture 20, xpPerStructureKill 10 }`、`VETERANCY_MAX_RANK = 3`、`VET_RETREAT_HP_RATIO = 0.5`(match.ts)。

**計算例**: 装甲強襲が敵の装甲強襲(HP 300)を単独で倒すと `300 × 0.02 + 120 × 0.25 = 36`。小拠点を制圧(守備 200 + 拠点 400 を削ってとどめ)すると `600 × 0.02 + 20 = 32`。合計 68 ≥ 60 で「熟練」(rank 1): 攻撃 ×1.08、maxHp 300 → 324(HP が 150 なら 162 に)、視界 ×1.05。この部隊を失うと損失は `8 × 1.0 × 1.1 = 8.8`。「古参」(rank 3、xp ≥ 300)なら攻撃 ×1.24、maxHp 372、損失 10.4。
