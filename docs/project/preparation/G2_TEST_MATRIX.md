# G2のテスト・検査設計案

これはテストコードや実行結果ではない。[G2_DESIGN.md](G2_DESIGN.md)を実装する際の期待結果を固定する。G1合格・マージ後に配置/型を照合してから使用する。

## 固定fixture

すべてseed42。map生成、command検証、tick、視界、料金は通常関数を使い、fixtureだけ別の初期stateを生成する。fixtureに移動や撃破を強制する特別処理を置かない。部隊の初期位置・現在HPの上書きは初期化時だけ行い、schemaとscenarioIdで識別する。

| scenarioId | 通常との差                                                                        | 再現できること                                                             |
| ---------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| standard   | 設計4章の通常初期値/配置                                                          | 開始から実際に移動して制圧・収入・生産・研究する                           |
| g2-capture | A-01=(20,28)、A-02=(20,29)。他は通常                                              | 30tickで下拠点を制圧し、同tickから補給2/秒・研究1/秒が入る                 |
| g2-combat  | A-01=(20,20)、B-01=(22,20)、双方HP4/maxHP100。A-02=(10,20)、B-02=(30,20)。Cは通常 | 強襲が射程境界で撃ち合い、2tick目に相互撃破、両陣営チケット各8減           |
| g2-economy | A補給180/研究150、下拠点(20,28)をA所有HP100、他は通常                             | 120+60の予約で補給0、研究の前提/同時開始/支払い、キュー取消/完了を短く確認 |

fixtureに上記以外の差を入れない。通常設定と同じ開始待ち、同じB/C固定行動。テスト専用の純粋state builderで特定境界のHP/残tick等を構成する場合は、ユーザー向けscenarioと区別する。

追加の順序境界:

- I05: 同tickの取消→予約、予約→取消をseq順に適用し、命令順とリプレイが一致する。種類別の隠れた並替をしない。
- I06: tick=nで100tick研究を開始するとn+100で完了。remaining=1の生産はstep前取消なら返金、step後取消なら拒否する。

視界・描画の漏洩は型とNodeテストだけで完了にせず、DOM・pickを実ブラウザーで確かめる。正規の全情報診断は漏洩テストの通常view経路へ混ぜない。
