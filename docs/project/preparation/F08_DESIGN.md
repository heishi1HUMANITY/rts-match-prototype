# F08 6兵種・陸空水 設計

2026-10-12、F03/F04/F09がmainへ統合された `b98752572f805989e9957f2ffd2f26194f746903` を基点にする。F08は兵種定義から試合内操作までを一続きで実装する。F16の最終バランスは先取りせず、本書の数値は検査可能な暫定値。

## 採用する役割と基準値

既存の強襲/偵察のHP・攻撃・射程・視界・費用は維持する。旧仕様の毎秒damage、80単位の座標、文明/人数/再建は現行tickへ直輸入しない。新兵種は違いが画面と通常試合で分かる整数値を置く。

新研究は各分野のstage 1、費用5000 centi、前提なしとする。既存研究の充填式・基本収入・同時進行・排他を変えない。攻撃可否は兵種ごとのtarget setで表現し、0 damageを有効攻撃として扱わない。構造物は中立守備、拠点、渡河設備、現地勢力本拠を指す。

## 移動と位置

- 位置は既存セル＋`edgeProgress`でserializableに保持し、1辺にかかるtick数を兵種RulesMasterから読む。再指示/停止は現在進行中のセル境界を保ち、同じseed・command列で同じ結果にする。
- 陸は現行の地形・橋・索道判定。橋/索道の許可兵種は領域ではなく各設備のallowed unit IDsで保持し、陸上3種へ明示拡張する。索道の現行制限を維持し、航空/水上は設備を使わない。
- 空は地形を無視し、始点と目的セルのBresenham直線セル列を通る。移動tickはセル単位で処理し、途中経路も再現可能にする。
- 水はriverセルだけを4方向探索する。港から出て、河川の連結成分内だけ移動できる。海へ出る河口がない水路から別水域へ移動できない。海峡横断を暗黙に許さない。
- 通常move、march追跡、preview、B/Cの経路判断、tickごとのroute再検査は同じ領域照会を使う。敵位置は可視の間だけ追跡に使う。

## 生産とマスタ

- RulesMasterの全6兵種に領域、target별整数damage、HP、射程、視界、tick/セル、費用、生産tick、維持費、損失ticket、解放研究IDを定義する。各MatchState.rulesへ複製され、試合中不変。
- 強襲/偵察は開始時配備・生産可能。追加兵種は対応するunit-unlock研究の完了後にcommandで生産可能。拒否は資源・ID・queueを変えない。
- 陸/空は所有中で稼働するHQから出現し、水は自陣PORTから出現する。既存の生産commandのproduction site IDをHQ/PORT共通にし、portのセルに部隊をspawnする。未所有・未稼働・港不存在は理由付きで拒否。
- 生産UIはHQ/港選択と6兵種カードを表示する。未研究、資源不足、上限、queue、港なしを区別する。B/Cも同じcommandと資源制約を使い、利用可能な研究と港からロスターを選ぶ。
- RulesMaster schema 8、MatchState schema 14 / `f08-v1`。schema 7 masterから編集済み既存値を保持し、新3兵種と解放研究は既定値で補う一方向migrationを行う。schema 6以下の既存migration経路は維持する。schema13以前の診断replayは暗黙互換しない。diagnosticsに完全master snapshot/content IDを残す。

## 戦闘・回復・制圧・ticket

- 戦闘はtick開始時snapshotから同時集計。移動中も射程内の対象へ攻撃する。陣営を問わず標準優先は敵unit > 中立defender > base > crossing > local stronghold、同一順位は距離、ID順。対空車両は有効対象範囲内に航空unitがあれば最優先。
- targetごとに攻撃可能か判定する。march targetが攻撃不能なら射程内の別の有効対象へ通常優先で切り替える。攻撃不能な敵のHP/存在を新たに知るための情報漏洩を作らない。
- damage bonus研究は全兵種の有効damageへ加算し、対象別基礎damageが0の攻撃を解放しない。local factionの現行growth倍率を含め、固定小数の丸めをテストする。
- 中立defender/既存守備は陸・空・水を攻撃できる。F08で追加する兵種に固有の半減は設定しない。拠点上の非戦闘回復はHP上限まで、10tickごとに `ceil(maxHp×4/100)` とし、HQ中心の半径3セル以内で移動中でなく、直前tickにdamageを受けていない部隊に適用する。回復は同tickのcombatより後。
- 陸上で `canCaptureBase` がtrueの部隊だけが制圧できる。air/waterは拠点・守備へdamageを与えられるが所有を変えない。哨戒艇は水路上の橋/索道を攻撃でき、HP0で予定地へ戻す。その他の水上部隊はF08に存在しない。
- unit lossは兵種ごとのticket値を適用し、既存のHQ損失・試合結果条件を維持する。上限までの回復・同時撃破・local unitのticket非加算をテストする。

## 情報・表示・検査

- `FactionView`は自軍unitの完全状態と、可視敵の領域/種類/HP/整数1024位置だけを渡す。隠れた敵の経路、解放、費用、queue、港spawn判断は渡さない。可視敵の位置形式と補間は1024セル整数を維持する。
- HUDに日本語の兵種名と記号（強/偵/砲/空/ヘ/艇）、HP、領域、攻撃役割、解放状態を表示する。board tokenも色に加え記号を付け、水上/航空はセル移動補間を反映する。3D固有モデルは既存採用素材なしに一括追加しない。
- F08 test scenarioは全6兵種の研究/港/水路/陸空差、対空優先、0damage拒否、航空水上の制圧不可、移動中射撃、損失ticket、回復上限を短い操作で再現する。通常standard設定とは分ける。
- 画面検査は通常戦とF08 scenarioの両方を、PCと900×420横持ちで実施する。検査版のURL/commit/CI、ユーザーが確認する操作・期待表示、未検査項目をIssue/PRに記録する。
