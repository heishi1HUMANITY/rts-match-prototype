# F09 / Issue #21 研究ツリー設計

2026-10-12時点の`main`（F17 / PR #34、F02 / PR #32マージ後）からの設計。F09で実装する範囲は、現行試合に効果を与えられる研究定義・効果・UI・NPC/診断接続。建築・兵種等の未実装解放先は、後続Issueが実体を実装するまでマスタに登録しない。

## 契約

- 研究は安定ID、分野（`power` / `logistics` / `information` / `engineering`）、段階、Centi費用、前提ID集合、排他ID集合、許可済み効果IDと値を持つ。
- 既定ツリーは4分野に分かれ、現行火力研究と橋/索道研究のID・費用・主効果を維持する。新しい基本数値はF16調整前の暫定値としてRulesMasterへ置く。
- 現時点で許可する効果は攻撃加算、部隊/拠点/渡河設備の視界加算、陣営の補給収入加算、部隊維持費の減額、渡河Tier解放。全て共通のpure照会をsimulation、NPC、HUDで共有する。
- 前提と排他は双方の参照が一致し、IDが存在し、自己参照/重複/循環がないことをマスタ検証で確認する。効果IDは実装レジストリにある値だけを許す。
- 完了研究は陣営ローカル。効果は完了済みIDから毎回集計し、別の隠れた状態キャッシュは持たない。敵研究はFactionViewへ渡さない。
- 経済tickで完了した効果は次tickから適用。command時バンクだけで完了した場合、即時に次の戦闘/可視化計算から使う。

## 既存ルールの維持

基本研究所得2 centi/tick（0.2pt/秒）、拠点所得、選択中だけの充填、未指定時バンク、研究別の進捗保持、余剰のバンク、同じ研究の再入力no-op、完了時の自動次選択なし、脱落/停止時の停止を維持する。旧固定待ち時間、予約列、一括課金へ戻さない。解放される施設・兵種は既存commandが実際に利用できる状態になってから研究へ追加する。

## 状態と版

研究IDの拡張と研究効果を持つRulesMasterへschema 7、MatchStateへschema 13 / rules `f09-v1`を割り当てる。旧MatchState/診断は暗黙読込しない。保存済みmaster schema 6は既定研究ノードを追加し既存6研究の編集済み値を保つ明示移行を行い、移行後validatorへ通す。

## 検査シナリオ

1. NPC停止の研究シナリオで各分野のカード、必要量/前提/排他/実効果を読む。
2. 火力研究の完了で同時交戦damageが変わり、橋研究完了で対応Tierだけ建設可能になる。
3. 情報研究の前後で自軍視界が更新し、兵站研究の前後で収入または維持費の内訳が変わる。
4. 研究途中に別分野へ切替、解除、再選択し、進捗保存・基本所得・余剰バンクを確認する。
5. B/Cが公開/自己viewだけから研究し、同一seed/入力の診断replayが一致する。敵研究/視界外情報は通常viewに出ない。
6. 完了後のpause/resume、elimination、reset/replayで充填・効果・HUDが整合する。

値の費用・効果量は通常試合の到達時間がF16で確定するまで暫定とし、F16が全分野の到達可能性を測定する。
