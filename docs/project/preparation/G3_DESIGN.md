# G3: NPCと試合の決着

G2合格版（PR #10、main 36d845bb650298cb33c7acfdd7c07c843f4fd584）を基点に、ユーザーの次段階着手依頼で実装する。G1のドラッグ移動とG2の研究充填方式を維持する。数値はプロトタイプの暫定値であり、完成バランスではない。

## ふるまいと採用理由

通常設定は人間AとNPC B/C、5分（3,000tick）の対戦。従来の30分仕様は試作の確認には長いため採用しない。敵は視界・補給・研究ポイント・生産時間・部隊上限を共有する。AIは毎秒、可視情報から研究・生産・探索・制圧・防衛・進軍を判断する。難易度や無料資源補正は追加しない。

脱落はチケット0、または首都破壊かつ生存部隊0。首都だけの破壊では残軍が戦闘・制圧でき、基本研究収入も続く。G3では再建機能を追加しない。チケットを失った軍が資源を無限に使って残存する状態を避けるため、旧版の「チケット0だけでは脱落しない」は採用しない。

脱落時は部隊を除去し、首都をHP0、所有拠点を中立HP0、制圧・生産・研究指定を解除する。資源と研究進捗は記録として保持するが以降の収入・研究・生産を止める。首都の原所有陣営は記録として保持する。全陣営の脱落を同じsnapshotで判定し、同時脱落の順位を走査順に依存させない。

人間脱落後は終了まで観戦する。探索済み地形と記憶、公開チケット・脱落情報の範囲で観戦し、敵の全情報へ切り替えない。新しい自軍視界は得られない。カメラと一時停止・再開は利用可能、部隊・生産・研究操作は拒否する。

## 決着と順位

生存1軍ならその軍が勝利、0軍なら全陣営脱落で引き分け。時間切れでは生存軍を残チケット降順に並べ、同点は同順位。脱落軍は生存軍より下で、脱落が遅い軍ほど上位、同時脱落は同順位（1位・1位・3位方式）。陣営IDは表示順だけに用い、勝者を恣意的に選ばない。全滅結果でも異なる脱落時刻がある場合は順位規則を維持する。タイムアウトと全滅が重なった場合は残存数の決着を優先。

終了時に公開結果（理由、終了tick、全陣営の順位・チケット・脱落理由）を固定し、ルールを停止する。終了後の全commandを拒否する。結果ダイアログから同じseed・scenarioで再戦、または設定へ戻る。再戦は資源・部隊・研究・探索・結果・命令履歴・選択・入力・タイマーを初期化する。

## 実装境界と順序

schema5 / rules `g3-v1`。旧版診断JSONの互換読込みは提供しない。

- `src/ai/strategy.ts`: `decideBotCommands(FactionView)`。完全なMatchStateを受け取らず、永続内部状態を持たない。公開地形と拠点座標は探索目標に使えるが未知所有者は推測して確定扱いしない。
- `src/runtime/advance.ts`: 初期脱落・終了を解決し、毎10tickに同じ元snapshotからB/Cのviewを作成、B→C順で共通commandを適用、simulation tickを進める。人間履歴だけを保存し、replayでも同じadvanceでNPC命令を再生成する。
- `src/simulation`: 移動→同時交戦→制圧→経済/研究→生産→チケット→脱落/決着→最終視界。start commandとstep冒頭にも初期脱落・決着を解決し、ticket0のfixtureで攻撃や収入を与えない。
- 拠点チケット圧力は生存Nに対し `max(0,min(6,他軍拠点数−(N−1)×自軍拠点数))×10Centi/秒`。3軍時はG2と同じ、2軍時も拠点差が圧力になる。
- UIは終了時だけモーダル結果を表示し、通常の盤面を塞がない。白/明灰の面と陣営色＋記号を維持。native dialogで背景入力を止め、再戦へフォーカスする。横持ち900×420で高さを制限しスクロール可能にする。

## 短時間検査

全scenarioは同じルールを使用する。G2検査3件のみNPC方針を止め、従来の手動検査を維持する。

- `standard`: 通常5分、NPC2陣営。
- `g3-timeout`: 20秒（200tick）で時間切れ。初期チケットは通常値。
- `g3-elimination`: B/Cの初期チケット0。開始時に同時脱落しA勝利。
- `g3-mutual`: 全軍の初期チケット0。開始時に全滅引き分け。
- `g3-spectate`: Aの初期チケット0、20秒制。開始時にA脱落、観戦後に結果。

fixtureは初期チケットと制限時間だけを変え、決着や資源の特例を入れない。

## 担当と完了条件

NPC担当はaiとruntime/advanceのみ、決着担当はsimulationのみ、親はruntime既存・UI・docs・統合、独立レビュアーは読み取り専用。共通型を先行し編集競合を避ける。

ルール・AI・runtimeで、視界境界、合法支払い、複数seed、同時脱落、時間切れ同点、首都喪失後残軍、終了後入力、観戦、リプレイ、再戦を検証する。全チェックとCIを実施し、起動URLと画面確認手順を用意する。ブラウザー自動操作は以前の安全チェックによるURLプロトコル拒否を回避せず、実画面・タッチ未検査を記録する。ユーザー合格前にマージしない。
