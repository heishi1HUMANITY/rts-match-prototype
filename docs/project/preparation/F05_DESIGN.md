# F05 / Issue #17 中立守備・拠点制圧の実装契約

2026-10-12時点のmain `0bc7a00`（F04 merged、schema 9 / rules f04-v1）を基点にする。F08 (#20)は未着手のため、現在の強襲/偵察だけで動く範囲を実装し、攻撃対象と制圧資格の共通契約を先行させる。F08の追加兵種は含めない。

## 対象と状態

- 中立の小/中/大拠点は、単一の守備NPCを表す集約守備HPを持つ。守備状態は`BaseState`内に保存し、Faction、通常部隊、チケット順位、NPC生産数へ加えない。首都と陣営所有拠点には守備を配置しない。
- 中立拠点は初期状態で拠点HPと守備HPが全快。陣営所有拠点を破壊して中立へ戻したときも両方を全快し、守備を再配置する。
- RulesMasterは拠点規模ごとに守備最大HP、毎tick攻撃力、射程、復活時間を持つ。初期仮値は小=60/1/2/300、中=100/2/3/300、大=160/3/3/300（HP / damage per 0.1秒tick / セル / tick）。F16の再調整前。
- `defenses.respawnEnabled`をマスタ設定で切り替える。標準はtrue。falseでも試合開始時には守備が配置されるが、守備撃破後の時間復活と、所有拠点破壊時の守備再配置を止める。既に進行中の試合には適用せず、新規試合から適用する。

## 戦闘・制圧順

1. 移動後の同じsnapshotから全陣営部隊の標的を選ぶ。可視の敵部隊、射程内の中立守備、敵または守備撃破済みの中立拠点、渡河設備の順に選び、同種標的は距離/id順とする。拠点へのmarchは守備がいる間、守備を先に攻撃する。
2. 中立守備は射程内の最寄り生存部隊を攻撃する。同tickの全部隊・全守備のダメージを一括計算し、撃破済み守備は同tickの拠点攻撃を防ぐ（余剰ダメージを拠点へ移さない）。
3. 守備撃破後は部隊が拠点HPを削る。拠点HPが0になった後、守備のない中立拠点に、制圧可能部隊が半径内へ1陣営だけ存在し続けると既存の制圧時間で所有変更し、拠点HPを最大値の30%にする。競合または離脱で進捗を破棄する。空中/水上移動の後続兵種は共通capability契約で制圧不可にできる。
4. 守備復活設定が有効な場合、守備撃破後に制圧可能部隊が半径内に300連続tickいないと、守備と拠点HPを全快する。接近中の陣営がいれば復活時計を0へ戻す。設定無効時は守備を復活せず、拠点HPも撃破時の状態を保つ。守備がない間は中立拠点への収入/チケット重みは発生しない。
5. 同時に拠点HPを0にした場合は現在の地上部隊による唯一の制圧資格者が制圧を始める。複数陣営がいる場合は全陣営が保留となり、Faction ID順で優先しない。首都破壊・既存チケット損失の処理は現行順を維持する。

- 有効/無効どちらの設定でも、所有拠点の破壊で拠点HPは全快して中立へ戻る。有効なら守備を全快して配置し、無効なら守備なしにする。

## 情報境界・AI・UI

- 守備HPは拠点が現在視界内、または所有拠点の場合だけ現在値を公開する。視界外の記憶は最後に観測した守備HPとtick。未観測拠点の守備状態は非公開。守備の攻撃は距離だけで判定し、守備を陣営の視界源にしない。
- B/Cは既存のFactionViewと共通combat/capture処理だけを使う。中立守備はB/Cも攻撃し、B/Cも守備を倒してから拠点を制圧する。守備撃破報酬は追加しない。
- HUD/拠点ラベルは守備HP、拠点HP、制圧進捗を分けて表示し、順序を短く説明する。短時間シナリオではAの2部隊をOUT-03近くへ置き、NPC命令を停止する。通常試合の守備と分離する。

## 検証契約

- 守備生存中に拠点HPへ損傷しない。同tick撃破は次tick以降に拠点へ通る。
- 複数陣営からの同時守備攻撃を同じsnapshotで反映し、守備や拠点を陣営順で処理しない。
- 守備撃破後に拠点を破壊し、単独陸上部隊だけが時間条件を満たして所有変更できる。競合、離脱、撃破、復活待ち、拠点再中立化を検証する。
- viewは可視/記憶/未観測の守備情報境界を保つ。NPCは同じ費用・戦闘・制圧資格を使う。
- JSON往復、同じcommand履歴のdiagnostic replay、pause/finish/resetを確認する。ユーザー検査では開始、守備撃破、拠点HP0、単独制圧、敵に拠点を落とされた際の守備復活を目視する。
- マスタで復活を無効にして新規試合を始め、300tick後も守備が復活しないこと、所有拠点を破壊した中立拠点へ守備が再配置されないことを確認する。

## バージョン

RulesMaster schema 5、MatchState schema 11 / rules `f05-v2`。schema3 masterは既存値を保持してF05守備設定を標準値で補い、schema4 masterは復活設定を有効にしてschema5へ移行する。診断replayは旧schema/rulesを拒否する。
