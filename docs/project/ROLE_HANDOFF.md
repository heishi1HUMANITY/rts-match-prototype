# モデル別の役割と引き継ぎ契約

この契約は会話履歴や担当者名に依存しない。担当交代・会話再開・Issue番号だけの依頼でも、AGENTSと本書を読み、担当役割と実際に使うモデルを確認する。ユーザーの明示変更があるまで維持する。

## 担当範囲

| 担当                       | 行うこと                                                                                    | 完了・停止条件                          |
| -------------------------- | ------------------------------------------------------------------------------------------- | --------------------------------------- |
| 設計担当（上位モデル）     | ソースの読み取り調査、詳細設計、Issue・依存・受入条件、シナリオ草案、gate・CP割当、採否整理 | 引き継ぎを保存し実装前に停止            |
| GPT-6 luna（`gpt-6-luna`） | コード・テスト・e2e・CI実装、実行検証、統合、PR作成、レビュー指摘修正、DoD確認・マージ      | WORKFLOWのDoDとCPへの引き渡し           |
| レビューモデル             | 実装とは別会話で固定headを読み取り専用照合                                                  | 受入条件別OK/NGと根拠。修正はlunaへ返す |
| ユーザー                   | 採否判断、CPごとの通常1試合、差し戻し                                                       | 判断またはCP結果を通常の言葉で伝える    |

設計担当はコード・テスト・CIを編集せず、テスト実行・ビルド・ブラウザ検証・PR修正も引き取らない。短い修正、緊急対応、子エージェントによる実装、親モデルでの統合も同じ制限の対象。疑似コードは設計文書内に留める。

ユーザーが直接依頼した運用文書の改定は設計担当が文書・文書テンプレートだけ編集し、整形・参照検査・独立した文書レビュー・文書PR対応を行ってよい。この例外はゲーム実装やCIスクリプト改修を含まない。機能実装の検証はluna、CI結果はPRの根拠として扱う。

## 引き継ぎの必須内容

設計担当が[実装指示テンプレート](templates/IMPLEMENTATION.md)を埋め、リポジトリの設計文書または対象Issueへ保存する。Issueから設計版と引き継ぎを辿れるようにする。チャットや子エージェントの記憶だけに置かない。

1. 対象Issue・CP・gate・ユーザー検査の要否と理由、依頼範囲と対象外。
2. 最新mainの参照基点、必須依存と充足状況、既存PR・未コミット変更の有無。
3. データ・command検証・tick順序・視界・NPC・UI・保存/移行・診断の契約。非該当も理由を記す。
4. ID付きの自動判定可能な受入条件とSCENARIOS項目、追加テストの狙い・境界条件・検証方法。
5. 編集可能ファイルと共有箇所、lunaが決めてよい詳細、設計担当へ戻す契約変更、未決定事項。
6. 指定実装モデル、独立レビューと最大2修正巡、PR/マージ/CPへの完了条件。

## 実装開始時の確認

GPT-6 luna担当が実際のモデル設定を確認し、対象Issueへ「役割 / 実モデルID / 引き継ぎ参照先 / 基点 / 依存照合 / 残る設計不足」を記録する。自己申告の役割名だけでモデル切替済みにしない。必須の設計不足は設計担当へ戻し、ユーザーに実装プロンプトを作り直させない。設計完了だけではflow:implementingへ移さず、lunaの着手時に移す。

モデル切替は利用環境の設定で行う。新しいチャットの作成・既存チャットへの送信はユーザーの明示指示とツールの権限に従う。切替を実行・確認できない場合は引き継ぎを保存し、次に必要な操作を1行で伝えて停止する。上位モデル、親モデルを継承した子、別モデルで実装を代行しない。代替モデルや担当範囲の変更はユーザーの明示指示が必要。

## 交代・差し戻し

交代する設計担当は対象Issue・最新main・保存済み設計・採否記録を再照合し、同じテンプレートで引き継ぐ。担当者変更で設計/実装の境界を変えない。契約変更が必要ならlunaが影響と質問を保存し、設計担当は設計文書・受入条件だけを改訂する。コード修正・再検証・PR対応はlunaが継続する。

CPが閉じるたびに設計担当はNG機能と次CPのIssueだけ計画を見直す。ユーザーには毎回、次の判断・モデル切替・CPプレイなど必要な操作を1行で示す。
