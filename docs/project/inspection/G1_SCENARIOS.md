# G1: 盤面・移動の検査シナリオ

対象Issue: [G1 #2](https://github.com/heishi1HUMANITY/rts-match-prototype/issues/2)。対象commitと検査回は親がIssue/PRの検査依頼に記録する。以下のユーザー結果はすべて未検査。

## 起動と設定

Node.js 24.x / npm 11〜12で、リポジトリ直下から `npm ci`、`npm run dev` を実行し、表示されたURLを開く。ビルド版は `npm run build`、`npm run preview` で開く。ネットワーク公開は行わない。

初期seedは42。「検査設定」のseedを42にし「適用してリセット」を押すと同じ初期地形・配置へ戻る。0、43、4294967295も指定できる。通常のG1と検査用の移動ルールは同じ。すべてのseedで孤立セル(30,10)とその周囲8セルの障害物を予約している。NPC2陣営は静止し、戦闘・生産・勝敗・短時間試合はまだない。

## G1-r02の追加確認（R01）

- 部隊からドラッグするとカメラは動かず、移動先の目印が出る。離すまでは新しい移動を開始しない。
- HUD上または盤面の外で離す、Escapeで取消す、2本目の指を追加する場合は移動せず、目印が消える。
- 障害物/孤立セルへのdropは理由を示し、以前の経路を維持する。
- 開始前/一時停止中に部隊をドラッグしても移動しない。地面からのカメラ操作は可能。
- 敵部隊のdragでは敵もカメラも動かない。自軍を押して選択→地面を押す補助操作も残る。

## 検証の区別（自動テストと実機）

自動テストはseed再現、地形接続、命令拒否、経路・停止・再指示、固定tick、履歴リプレイ、PointerEventの判定を検証する。ブラウザーのマウス確認と画面寸法変更はスマホ実機のタッチ確認と区別し、実行結果を検査依頼へ記録する。実機タッチ、WebGLコンテキスト喪失/復旧、性能数値は実測なしに検証済みとしない。
