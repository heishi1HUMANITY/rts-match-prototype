# 試作から必要ゲームプレイ全体まで

全段階は世界観知識不要の1v1v1に限定する。完了は実測とテストで判断する。

実装の分割・依存・検査項目は [TASKS](TASKS.md)、指示と修正の手順は [WORKFLOW](WORKFLOW.md) を参照。
M1〜M3はG1〜G3の最小試作の検査区切り。M4/G4の最終合格は、下記の必要ゲームプレイ拡張を含めて仕上げと初見検証を行う。各機能に必要なUIはその実装時に用意する。

| 段階              | 作業                                                     | 完了条件                                                                           |
| ----------------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| M0 開発基盤       | 新規Git、docs/artwork継承、AGENTS、CI、起動、状態契約    | fresh cloneでnpm ci/check、参照ハッシュ検査、GitHub CI成功                         |
| M1 盤面・入力     | Three.js盤面、seed地形、カメラ、部隊選択、移動、固定tick | 人間の部隊のみ操作可能。タッチ/マウスとHUD入力が競合せず、移動がテストで再現できる |
| M2 対戦ループ     | 補給、生産、拠点、交戦、最小の研究、チケット             | 資源を二重使用できず、拠点の所有が収入・戦況へ反映される                           |
| M3 NPC・決着      | 2陣営AI、勝敗・時間切れ、結果、再戦                      | NPCが同じ制約で進軍・生産し、人間を含む三つ巴が終了。再戦へ状態を持ち越さない      |
| M4 初見プレイ検証 | mockに基づくHUD、研究、生産、操作ガイド、調整            | 900×420とPCで説明役なしに開始→制圧→生産→交戦→結果→再戦できる                       |

M1開始前に地形と進行、M2開始前に兵種と研究、M3開始前に勝敗の暫定ルールを決める。
固定値を旧版から流用する場合も採用理由と差分を記録する。
2026-10-11のユーザー指示により、[GAMEPLAY_COVERAGE.md](GAMEPLAY_COVERAGE.md) と [全体Issue #12](https://github.com/heishi1HUMANITY/rts-match-prototype/issues/12) で必要な試合内ゲームプレイを網羅する。最小試作の終了を全体完成としない。

拡張は複数部隊一括操作・対象追跡を先に、地形/兵種/研究→渡河建設/中立守備→拠点強化/防御施設/現地勢力/補給線→態勢/練度/戦闘予測/戦術能力→時間・再建・バランスの統合と進め、G4を全機能の初見検証で完了させる。詳細依存と機能別Issueは網羅表を参照。段階ごとのユーザー検査は維持する。
