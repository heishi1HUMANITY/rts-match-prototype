# 表示・入力境界と未提供機能

## 採用仕様（2026-10-16・未実装）

- 開始地点と隣人の部分的な情報を見て研究・拡張・標的を選べる表示にする。配置と戦力による判断を支え、操作速度や精密入力の巧さを勝ち筋として要求しない。
- 人間は常にA、物理開始地点をseedで選ぶ。陣営傾向の選択/seed割当の導線は導入時に採否を決める。現在提供している開始画面に実装済みとは扱わない。
- 研究段1〜3の非排他と段4の全分野排他、必要量増加、取得状態を色と記号で示す。専攻完成だけ全陣営へ通知し、その他の敵研究は公開しない。
- PCと900×420で2戦線・通知・生産・研究・結果・再戦を扱えることを確認する。通常試行は100×100版を表示し、描画・カメラ・入力境界・ミニマップは盤面寸法に追従する。100×100への寸法対応は[地形・渡河設備](WORLD.md)、研究の内容は[補給・生産・研究](ECONOMY.md)に従う。
- 行軍先の戦闘予測は採用済み・未実装。自軍の選択部隊と可視敵/守備/施設/拠点から勝敗見込み・所要時間・損耗・前提を示す。記憶情報の古さと予測誤差を明示し、隠れた情報を混ぜず、予測だけで命令や資源を変更しない。
- 航空経路・対空初発見通知/カメラ/最終観測射程、地点砲撃の予告等は後続検討。具体操作と認知猶予の条件は[兵種・戦闘・回復](COMBAT.md)を参照する。

採否の根拠は[決定記録](../DECISIONS.md)と[Issue #79](https://github.com/heishi1HUMANITY/rts-match-prototype/issues/79)。この節は採用された変更と未確定の範囲を示す。以下は現在のコードの動作であり、上記の変更が実装済み・検証済みという意味ではない。

## 現行実装

### 現行インターフェース

- Three.js盤面とDOM HUD。陣営はA/B/C、色と記号を併記する。PCと横持ち900×420が検査対象。グリッド・簡易部隊記号は試作用で、最終アートやG4完成を意味しない。
- 自部隊起点のドラッグは命令、地面起点はカメラ移動。タップ選択→地面タップを補助操作として残す。ホイール/ピンチでズーム。HUD上/盤外drop、取消、複数指の競合では移動命令を出さない。
- 生産/取消、研究指定/解除、建築、拠点強化、駐留、作戦指令、マスタ編集、開始/一時停止/再開/リセット、結果/再戦を提供する。操作ルールは各機能仕様へ置く。
- 生産・研究・拠点・渡河・施設・作戦は盤面横の常設ドックから切り替える。初期表示は生産。同じ操作の再選択では閉じず、内容を閉じても操作タブは残る。拠点選択は該当する拠点操作を直接開く。ドックの領域を盤面から除き、中央へ重ねない。
- 検査設定は適用成功時に閉じ、操作タブを遮らない。不正な設定では開いたまま修正できる。
- タブを隠すと自動停止、復帰後は明示再開。描画復旧待ち等の拒否はruntimeで区別する。時計は1フレーム最大5tick、過大な遅延はdrop時間として診断へ記録する。
- 通常UI/render/対戦AIは `FactionView` を使う。不可視の敵詳細は渡さない。拠点/施設/渡河設備の観測記憶は現在値と区別する。煙幕と視界妨害は [作戦指令](TACTICS.md)、施設妨害は [拠点・守備・施設](BASES.md)。
- 視界マスクは初回描画前から盤面寸法のCanvasを使い、寸法が変わるとGPUテクスチャを再作成する。Canvasの既定300×150のGPU領域へ異なる寸法の画素を部分更新しない。斜めカメラによるセル対応ずれを避けるため地面近くへ置き、simulationが渡す視界結果をそのまま使う。

### 現在提供しない機能

- 補給線: 首都への補給線接続判定と切断による機能低下はない。所有稼働拠点の収入に補給線条件を加えない。
- 態勢・集結点・自動退避・練度: いずれも提供しない。通常の首都近傍回復と駐留は利用できる。
- 戦闘予測: 行軍先の戦闘予測は未提供。追跡・行軍操作を予測機能と読み替えない。
- 試合外メタ、オンライン通信、世界観、課金は対象外。現地勢力・徘徊NPCの現状は [対戦NPC・現地勢力](NPC.md)。この現行実装の節は現在の動作だけを記載する。
