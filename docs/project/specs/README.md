# 現行機能仕様の入口

このディレクトリはゲームの現行機能をまとめた独立した参照資料。初回整理の基準はコードの `a6a9f16`。機能の動作・条件・制約と実装参照を記載し、開発手順・進捗管理・承認手続きを扱わない。この入口と各仕様だけで読み進められる。

AIは次の順で必要な部分だけ読む。

1. 下の機能名・機能IDから仕様を選ぶ。機能IDは資料内の検索キーとして使用する。
2. 相互作用を確認するときは各仕様末尾の関連仕様を読む。
3. 詳細確認には [registry.json](registry.json) の `sources` から実装へ進む。テストは各仕様末尾を参照する。
4. 数値は [DEFAULT_RULES](../../../src/simulation/rules.ts) とその入力元 [config.ts](../../../src/simulation/config.ts) を読む。試合中は `MatchState.rules` が適用値で、保存済みマスタや標準値とは異なる場合がある。

## 記載範囲

- 現在の動作、前提条件、例外、設定項目、機能間の関係を記載する。将来案や過去の設計経緯は含めない。
- 提供していない機能と標準で無効の機能は本文で区別する。動作の記述はプレイ品質の評価を意味しない。
- コードと本文に差があれば、実装・テストを確認して差異を明示する。

## リンクと更新対象の構造

`registry.json` は安定した仕様ID、機能ID、文書パス、実装パス、確認済み実装のSHA-256を持つ。行番号・見出しの自動生成アンカーに依存せず、仕様IDとファイルへの相対リンクで参照する。ファイルは原則改名しない。統合・分割時は旧パスに案内を残し、対応表と全参照を更新する。

数値の正本は実装マスタとし、仕様本文へ可変の数値表を重複転記しない。本文には設定キーと意味を記す。関連仕様は相互リンクで参照し、同じルールを複数文書へ複製しない。

## 資料の整合性確認（任意実行）

資料専用の検査コマンドを用意している。通常の開発チェックからは独立しており、資料を確認・更新するときに単独で使用できる。

```sh
npm run specs:check
# 表示された担当仕様と関連仕様を確認・修正した後、確認したIDだけ指定
npm run specs:review -- MATCH ECONOMY
npm run specs:check
```

`specs:check` は実装との差分から見直し候補の仕様IDを示す。本文と関連仕様を確認し、必要な修正後に `specs:review` で参照した実装のハッシュを記録できる。文言変更が不要な場合も確認後に記録する。ハッシュは仕様の自動生成・正しさの証明ではなく、参照した実装の記録。本文の意味の更新漏れまでは自動判定できない。

検査対象は、仕様内の相対リンク、明示アンカー、対応表の参照先、実装ハッシュ、未登録の本番srcファイル、F01〜F21の割当。外部URLの死活と他の資料全体のリンクは検査範囲外。改行はLF/CRLFを正規化して比較する。
