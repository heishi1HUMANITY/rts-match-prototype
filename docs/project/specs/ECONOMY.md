# 補給・生産・研究

## 採用仕様（研究構造・費用は#81実装済み、経済は#82未実装）

研究構造と費用は#81で実装済み。#82の定額経済・拠点/部隊上限・逆転検証は未実装で、以下の完了時刻は#81の現在標準収入を使った結果である。#82後に同じ試験列を新しい標準収入で再計算する。

### 定額収入と領土の役割

- 研究・補給収入は所有拠点数に依存しない定額とする。旧「基本研究収入＋所有拠点ごとの加算」を置き換える。研究などの効果で定額を補正しても、所有拠点数を通じて収入を増やさない。
- 維持費・支払い・生産枠の共通検証を維持する。領土が効くのはチケット倍率・部隊上限・足場（生産位置・駐留・視界・渡河）のみ。拠点種別・強化の収入効果は耐久・視界・上限寄与・足場機能へ置き換える。代替効果の具体値は未確定。
- 逆転の不変条件は (1) `2 × baseUnits > maxUnits`、(2) baseUnitsの部隊を駐留したHQがmaxUnitsの攻撃を単独で凌げる、(3) 最下位の1拠点奪還時間がチケット寿命より十分短いこと。定額値・上限・HQ駐留・チケット領土倍率の帯域はこれらから算出する。
- 防衛の代表編成・研究・攻撃条件・継戦時間、奪還の必要余裕を実装時に明示する。HQを全編成に対して永久無敵にする意味ではない。領土喪失だけで既存部隊を削除しない。

### 研究の希少性

- 戦力・兵站・情報・工兵の4分野、段1〜4。段1〜3は排他なし。同分野の前段のいずれかを前提にするOR条件。段4専攻だけ全分野を通じて1つに制限する。
- 完了数に応じた必要量増加はマスタ係数4.5%/完了、必要量は基礎値×(1+完了数×係数)を切り上げる。stage1基礎は通常7,200 centi (火力1のみ9,600)、stage2は15,600、stage3は21,600、stage4は27,600。現在実行できる登録ノードは27件。標準20分/開始時収入1.2pt/sで、火力1→2→3→戦力専攻→砲兵→対空→航空→海軍→補給線→整備の10件を完了する実tick計算は11,384tick (94.87%)、10/27=37.04%。専攻は6,731tick (56.09%)に完成する。これは#82の定額収入化後を検証した結果ではない。
- 各研究の必要量は初めて正の充填が発生した時点の完了数で算定し、次ノード選択だけでは安値を予約しない。以後は別研究の完了や切替でもその研究の必要量を固定する。段1〜3は同分野の直前段のいずれかを前提とするOR条件、段4は全4分野から1専攻のみ。
- 比率分母は現時点で実行可能な27ノード。後続Issueで未実装効果を持つノードを追加した後の全ツリー比率ではない。必要量は最初の正の寄与時に固定し、別研究完了後も既存進捗/確定量を保持する。
- 充填式、未指定バンク、研究別進捗保持、完了時の指定解除、次研究を自動選択しないことを維持する。専攻完成だけ全陣営へ通知し、その他の敵研究は非公開。
- 研究は使える兵種・進出先・戦い方・対抗手段を変える。stage4各分野の効果は現在実装済み効果から選ぶ。未実装の効果を登録だけして利用可能と扱わない。旧コスト80/160/280/450・研究収入3.3/秒は確定値ではない。

### 陣営傾向と生産位置

- 陣営傾向は最終成果物に必須。先にマスタへ枠を定義し全陣営を中立にする。中立地形の公平性と3開始地点の道筋を確認した後、道筋の初速を与える傾向を導入する。
- 傾向はA/B/C固定にしない。人間が選ぶかseedで割り当てるかは導入時の採否事項。帯域逸脱は地形でなく傾向値を直す。導入前提の地形評価は[地形・渡河設備](WORLD.md)を参照する。
- 前線生産・回復、戦時経済の生産補正、全域観測、封鎖等は後続専攻の検討対象。具体的効果と数値は未確定。現時点で全所有拠点から生産できると解釈しない。

採否の根拠は[決定記録](../DECISIONS.md)と[Issue #79](https://github.com/heishi1HUMANITY/rts-match-prototype/issues/79)。この節は採用された変更と未確定の範囲を示す。研究構造/費用は#81で実装済み、定額経済・逆転条件は#82で実装する。

## 現行実装

### 経済と生産

- 資源はCenti整数（100で1ポイント）。生存陣営に基本研究収入を与え、所有稼働拠点から規模・強化・研究に応じた補給/研究収入を加える。部隊ごとの維持費を引き、補給は0未満にしない。赤字時に部隊を自動除去しない。
- 自首都で陸/空部隊、自港で水上部隊を生産する。研究解放、資源、キュー、部隊上限を同時に検証。生産予約時に費用と部隊枠を確保し、IDを予約する。
- 上限は `min(maxUnits, baseUnits + 稼働する自非首都拠点数 × unitsPerOwnedBase)`。現存部隊＋予約数で新規受付を判定。領土を失っても既存部隊を削除せず、現存数が上限以上なら生産進行を止める。
- 陣営ごとの直列キュー。tick開始時にactiveだったjobだけ進み、完成時は首都/港へ出現、次jobをactiveにする。取消は支払済み全額を返す。作戦「緊急増産」は [作戦指令](TACTICS.md)。

### 研究充填

- 選択対象へ既存バンクを直ちに充填し、その後の収入も必要量まで充填する。必要量到達で即完了し、余りはバンク。研究未指定なら全量バンク。
- 指定解除・切替でも研究ID別進捗を保持し、返金・移し替えはしない。同選択の再入力で二重消費しない。完了時は選択解除し、次研究を自動選択しない。
- 研究は戦力/兵站/情報/工兵の4分野。安定ID、段階、必要量、前提ID集合、対称排他ID集合、登録済み効果の集合を定義する。
- 完了済み、前提未達、完了済み研究との排他は拒否。効果はdamage、vision、補給収入、維持費軽減、渡河/兵種/拠点Lv/施設解放、施設工期短縮のみ。自由記述の任意コードを実行しない。
- 経済後に充填完了した効果は、そのtickの既に終わった戦闘へ遡及しない。pauseでは収入も研究も停止。resetでバンク・選択・進捗・完了を初期化。

### 研究定義編集

研究定義編集はマスタ上で研究IDの追加・削除・変更、前提/排他/登録済み効果の接続を提供する。重複・存在しない参照・循環・不正な効果等を検証し、不正な定義を試合へ適用しない。保存済み定義の変更は進行中試合へ反映しない。
