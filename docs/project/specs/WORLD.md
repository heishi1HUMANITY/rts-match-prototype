# 地形・渡河設備

## 採用仕様（2026-10-16・未実装）

- マップは構造固定の複数種類とする。寸法・地形・拠点・渡河設備・港・開始地点3箇所を、マップごとに1ファイルの定義データへまとめる。seedの変動は進路の形を変えない範囲に限る。
- 人間は常に陣営A。Aの物理的な開始地点をseedで3箇所から選び、B/C、所有拠点、港、初期部隊も対応付ける。陣営IDと地理的位置を固定しない。同seed・同定義では同じ初期状態となる。
- 地形設計の前に、現行40×40の座標を2.5倍にした100×100版を現行ルールで試す。現行版も保持する。セルの拡張・座標丸めは、川の連続性、両岸と設備、港と岸の隣接、初期配置と通行を壊さない規則を実装時に定義する。寸法だけ広げて旧配置を残した版にはしない。
- 最初の試行で見るのはHQ間移動の体感、900×420での2戦線把握、部隊上限9の過不足、決着要因、tick処理時間。この時点では研究・経済・速度・戦闘の新値を混ぜない。結果を新地形設計の入力にする。
- 各開始地点に、守りやすい進路と迂回されやすい進路、2つ以上の拡張先、地形に合う研究の道筋を持たせる。公平性は「成立する道筋が1つ以上あり、地形から道筋を選ぶNPCの開始地点別勝率が20〜50%」とする。HQ間の等距離や同専攻を入れ替えた勝率一致を条件にしない。
- 公平性評価は[対戦NPC・現地勢力](NPC.md)の道筋選択と組で行う。開始地点・陣営ID・傾向・道筋を分離し、seed・定義・マスタ版・終了理由を記録する。母数、引き分け・未決着の扱い、実行seed数は正式評価前に定義する。
- まず中立傾向の1枚目を帯域内に収め、3開始地点の道筋の違いをプレイ確認する。2枚目以降は単なる見た目違いでなく、成立する道筋の種類が異なることを条件に追加する。旧相談の100×100地形案は未採用。
- 渡河の建設前後、港・船の連続航路、増援・撤退・前線転用・第三陣営への介入も評価する。マップ定義と開始地点割当の再現は[マスタ管理・診断再現](MASTER.md)に従う。

採否の根拠は[決定記録](../DECISIONS.md)と[Issue #79](https://github.com/heishi1HUMANITY/rts-match-prototype/issues/79)。この節は採用された変更と未確定の範囲を示す。以下は現在のコードの動作であり、上記の変更が実装済み・検証済みという意味ではない。

## 現行実装

### 盤面と経路

- 旧40×40生成版を保持し、通常画面は試行用の `ring-three-fronts` 100×100版を使う。100版は旧版seed 0の地形・障害物を固定参照にし、各40セルの面を `[floor(2.5x), ceil(2.5(x+1)))` の2/3セル帯へ展開する。点アンカーは `round(2.5x)` へ丸め、渡河設備の岸間セルを連続再構成する。地形形状はseedで変わらない。
- 100版ではseedを3開始地点のA/B/C割当にだけ使う。Aは常に人間。拠点所有、港、初期部隊を同じ位置スロット置換で対応させる。定義ID/版、地形、寸法、開始割当、配置はMatchStateへ保存する。
- 40×40/100×100とも陸地、河岸、川、山と地形等級、中央島、港、首都/小/中/大拠点、橋・索道予定地を持つ。配置・地形形状は現行マスタの編集対象外。
- 陸上は通行可能セルと完成済み渡河設備、航空は地形を無視した直線、水上は川セルで移動する。港は哨戒艇の生産先。到達不能な移動命令は拒否する。
- 川・山の予定地表示だけでは通行権を与えない。橋3級は陸上4兵種、索道2級は斥候だけ通せる。陣営の経路計画は所有/観測済み設備を使い、実移動時にも設備状態を確認する。

### 建設・奪取・解体

- 所有する強襲部隊を予定地の岸へ隣接させ、`build-crossing` で開始する。橋I以外は対応する研究効果の完了が必要。開始時に補給を払い、同じ自工事の再入力は二重課金しない。
- 建設/解体は必要な部隊が隣接している間に進行する。工事中・所有済み・資源不足等は共通検証で拒否する。解体は自所有設備を対象とする。
- 完成設備は攻撃可能。撃破時は同時被害の一意最大陣営へ所有が移り、同率最大は中立化する。設備の変化で経路を再確認し、通れない区間へ進み続けない。
- 設備付属施設の喪失条件は [拠点・守備・施設](BASES.md)。現地勢力は完成経路を兵種制約に従って利用する。
