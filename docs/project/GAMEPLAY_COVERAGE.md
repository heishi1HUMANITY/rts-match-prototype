# 必要な試合内ゲームプレイの網羅

2026-10-11のユーザー指示「必要なゲームプレイはすべて用意する」に基づくスコープ補正。全体の進捗の正は [全体Issue #12](https://github.com/heishi1HUMANITY/rts-match-prototype/issues/12)。Issueを登録しただけでは機能の実装・検証済みを意味しない。

G1〜G4は最小の試作・検査手順として作った区切りであり、建築や中立NPCを含むゲームプレイ全体の完成を保証していなかった。初期対象外とした機能の後続Issueがなく、網羅の計画が不足していた。この文書で追跡先を用意し、G4の最終合格も拡張された全体の通しプレイに結び付ける。

## NPCの区別

- 対戦NPC B/C: 人間と同じ立場の対戦相手。G3/PR #11で実装し、ユーザーのマージ許可に基づきマージ済み。実画面の未検査範囲は残る。
- 中立守備NPC: 中立拠点を守る敵。F05。
- 現地勢力: 本拠・生産部隊・所有拠点を持つ独立勢力。F06。対戦順位の第4陣営と混同しない。
- 徘徊NPC: 定期出現する脅威。原仕様と計算モデルで存廃が矛盾しておりF07で採否・統合方法を確定する。黙って消さない。

## 実装順と統合

1. F01複数部隊の一括操作→F02対象追跡。今回ユーザーが挙げた操作改善を先に進める。
2. F17のマスタ管理基盤を導入し、調整パラメータをソース直書きから管理・検証・保存・新規試合適用・診断再現へ移す。その後F03地形/拠点規模と、F08兵種・F09研究の公開契約を整える。F04渡河建設、F05中立守備を検査できる単位で実装。
3. F10拠点強化/F11防御施設、F06現地勢力/F07徘徊、F12補給線を依存に沿って拡張。
4. F13態勢/集結点/練度、F14戦闘予測、F15戦術能力/合図を接続。
5. F16再建/時間/フェーズ/バランスを全体で調整し、G4のUI/ガイド/結果詳報と全ゲームプレイ通し検証で仕上げる。

F16の設計は地形・建築・NPCの前から行い、出現しないイベントや完了しない建築を後から発見しない。研究解放先と施設の実装順は循環依存を避ける公開契約を先に固定し、未実装効果の研究を選択可能にしない。各追加機能に必要なUI、B/Cの意思決定、視界境界、診断replay、短時間検査を同時に更新する。

## 初期試作との差と判断が必要な点

- G3の5分に対して旧イベントは8/9/18分。通常試合で登場する進行・建築・研究時間へ再設計する。旧30分を自動復活させない。
- G3は再建なし・チケット0脱落、旧版は首都再建あり。首都再建と脱落の仕様はF16で具体案を提示して確定する。承認済みG3のふるまいを黙って変更しない。
- G2の無人拠点30tick制圧と旧守備NPC→拠点HPの制圧はF05で置換/統合のルールを定義する。
- 研究はユーザー承認済みの充填式・未指定バンク・進捗保持・基本収入を維持。旧予約列/固定待ち時間は復活させない。
- 複数部隊移動と対象追跡は新しい明示要件で、元の単体固定地点移動だけでは満たさない。

試合外のアカウント、オンライン、永続育成、課金、物語・世界観の知識は既存の対象外を維持する。世界観演出と結び付いた作戦指令等は、試合内の戦術効果をF15で別に判断する。文明、アドオン、可変チーム人数まで無断で採用したことにはしない。採否を決める必要がある機能は未決定として追跡し、全体完了までに採用・代替・明示除外の根拠を残す。

## 全体の完了条件

内政→地形/渡河の建設→複数部隊の進軍/追跡→中立/敵との戦闘→研究/拠点強化/防衛→決着→再戦を通常設定で行えること。NPC B/Cも同じ費用と視界の範囲で利用すること。各機能の見た目・操作・理由表示がPCと横持ちで分かり、通常試合で使う機会があること。未実装、未検査、既知の制限を説明し、ユーザーのふるまい確認で合格すること。
