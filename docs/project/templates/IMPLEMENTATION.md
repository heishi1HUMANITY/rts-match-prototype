# GPT-6 lunaへの実装引き継ぎ

設計担当が記入し、対象Issueから恒久リンクする。未記入のまま実装を開始しない。非該当は理由を記す。[役割と引き継ぎ契約](../ROLE_HANDOFF.md)を交代時にも読む。
内部タスクの担当はユーザー検査・外部Issue編集・マージを行わない。

- 設計担当 / 設計版・恒久リンク:
- 実装担当 / 指定モデル: GPT-6 luna（`gpt-6-luna`）
- 実装担当が確認した実モデルID / Issueへの着手記録:
- 対象Issue / CP / gate / ユーザー検査の要否と理由:
- 作業場所・ブランチ:
- 基点commit:
- 既存PR / 未コミット変更の有無と保全方法:
- 目的（利用者に見える結果）:
- 前提タスク・採用済みの型/API:
- 必須依存の充足状況 / 推奨順:
- 読むもの: AGENTS.md、SCOPE、ARCHITECTURE、DECISIONS、WORKFLOW、TASKSの対象行、関連mock
- 編集可能なファイル/ディレクトリ:
- 共有ファイルの担当と変更を依頼する相手:
- 対象外:
- データ・command検証・tick順序・視界・NPC・UI・保存/移行・診断の契約または設計リンク:
- ID付きの自動判定可能な受入条件 / SCENARIOS項目 / 追加テストの狙い・境界条件:
- 暫定数値・理由 / 未決定事項:
- 完了条件:
- 検証コマンド・再現シナリオ:
- Windows/Linux check・references検査・該当e2e CI / 独立レビュー（最大2修正巡）:
- PR・マージ・CP票・#12反映の完了条件:
- 判断してよい事項 / 親へ戻す事項:
- 報告してほしい内容: 変更、実際の検証、未検証、仕様判断、変更ファイル、既知の問題

通常の実装判断は範囲内で進め、疑問だけを理由に停止しない。
契約変更や対象外ファイルの編集が必要な場合、親へ影響を報告して調整する。
旧コードやmockの疑似処理を正として移植しない。ユーザー合格を代行しない。

設計担当は必須欄を保存したら実装前に停止する。実装・テスト実行・統合・PR修正を引き取らない。lunaは実モデル・基点・依存・設計不足を照合し、Issueへ着手記録を残す。内部の部分担当は外部Issue編集・マージをせず、GPT-6 lunaの実装側親が統合・PR対応を担う。

lunaを利用できない場合は保存済み引き継ぎと必要な切替操作を報告して停止する。上位モデルや親モデルを継承した子による代行はしない。
