# ユーザー検査依頼 G**-r**

親が実際の結果で埋め、PR/Issueへ記録し、チャットへ短く要点を渡す。
「実装済み」と「ユーザー合格」を区別する。

- G / Issue / PR:
- ブランチ / 完全なcommit SHA:
- 検査用作業場所:
- 起動コマンド:
- 実際に確認したURL:
- URLが開けない場合のローカル起動手順:
- seed / シナリオの選び方 / 設定:
- 通常設定と検査用設定の違い:
- 今回できること / まだできないこと:
- 技術検証: コマンドと結果、CI URL、ブラウザ/端末/画面サイズ、実機かエミュレーションか
- 既知の問題と検査への影響:

| 検査ID | 操作手順       | 期待結果               | ユーザー結果 |
| ------ | -------------- | ---------------------- | ------------ |
| G\_-01 | 再現できる手順 | 画面上で判断できる結果 | 未検査       |

修正後の依頼では、対応したR番号、前回からの差分、再検査してほしい項目、未検査項目を付記する。

返信は「G** 検査OK」または「G**修正: 操作と困ったこと」でよい。
次のGも開始する場合は「マージしてG\_\_へ進めて」と依頼する。
