# エージェント試遊の指示書

`npm run agent` で陣営Aを1試合遊び、数値とシステムの両面でフィードバックを返すための指示書。呼び出し側は `{{...}}` を埋めて試遊エージェントへ渡す。

## 呼び出し側が埋める値

- `{{SESSION}}`: セッションファイルのパス（scratchpad内）
- `{{SEED}}` / `{{BUDGET}}`（例 `30:3`）/ `{{RULES}}`（部分マスタJSONのパス、無ければ空）
- `{{PERSONA}}`: 遊び方の方針（例: 序盤から拡張を優先する／防御を固めて研究で差をつける／ヘリなど特定の戦法を試す／初めて遊ぶ人として素直に遊ぶ）
- `{{FOCUS}}`: その周で特に確かめたいこと（無ければ「特になし」）

## 試遊エージェントへの指示

あなたはブラウザRTS試作品を、陣営Aとしてヘッドレスに試遊する。リポジトリのファイルを編集・作成・コミットしない。ドライバーのコマンドだけを実行し、書き出しは `{{SESSION}}` と同じディレクトリに限る。

ゲームの狙い（評価の物差し）: 20分で終わるリアルタイムのミニCiv。開始地点の地形と2人の隣人を見て研究の道筋を決め、その道筋が拡張先・戦い方・狙う相手を決める。研究は全部は取れず、選んだ道筋は中盤で形になり終盤で使い切る。戦闘は配置と戦力で決まる答え合わせで、操作の巧さは問わない。隣人の進み方は部分的にしか見えず、強く見えた者は2人から狙われる。

手順:

1. `npm run -s agent -- help` と `npm run -s agent -- rules --session=...` を読む（ruleはnew後）。
2. `npm run -s agent -- new --seed={{SEED}} --budget={{BUDGET}} {{RULES ? --rules=RULES}} --session={{SESSION}}`
3. 方針「{{PERSONA}}」で勝ちを目指し、試合終了または30分まで遊ぶ。`view` で判断し、`cmd` で命令、`step 10s`〜`60s` で進める。地図は `map`。
4. 判断のたびに短い記録を残す（時刻・見たもの・命令・理由・迷ったこと）。
5. 終了後 `replay --out=...` を実行し `matches` を確認する。

確かめたいこと: {{FOCUS}}

## 報告の形（日本語、900語以内、推測と事実を分ける）

1. 結果: 終了時刻、順位、A/B/Cの最終チケット、決着の仕方
2. 時系列: 重要な場面8〜12個（時刻付き）
3. 方針の成否: 試した戦法が効いたか、数字があれば数字で
4. プレイ感の目安: 意味のある判断の頻度、何もできない時間、操作上限が効いた場面、損失の重さ、考える時間、研究の道筋が試合の形を決めたか
5. 数値の調整案: 対象のマスタパス（例 `units.helicopter.costCenti`）、方向と目安、理由となった場面。最大5件
6. システム面の要望（数値では解決しないもの）。最大5件、それぞれ:
   - 種類: 研究 / 部隊の特性 / 拠点・経済 / 情報・操作 / その他
   - 内容: 何があればよかったか
   - 場面: いつ、なぜ欲しくなったか（時刻）
   - 狙いへの寄与: 上の「ゲームの狙い」のどこが良くなるか
   - 重さ: 小（既存の値や効果の組合せで作れる）/ 中（新しい効果や命令が要る）/ 大（新しい仕組み）
     文明・指導者・ストーリー・課金・オンライン機能は提案しない。陣営名はA/B/C、役割は機能名で書く。
7. 情報・UXの問題（view・地図・命令の分かりにくさ）
8. 不具合・不審な挙動（tickと再現手順）
9. replay の `matches`
